# RFC: Search-corpus serving leases and resource-admitted ingest

Status: **Proposed**. This document is a decision proposal, not an Accepted ADR or a release qualification.

Date: 2026-09-30. Source baseline: local `main@24e54ae57f0b2d145704eecdeb6d9c5233d61a03` without its concurrent uncommitted overlay. The RFC was authored in a separate worktree at that commit. The two commits since `dfea255d` change retrieval benchmark/oracle files only; the audited engine source is identical across that interval.

## Decision sought

1. Close the gap between resolving an `Active` search-corpus selector and acquiring its `QueryReadViewV2`. An un-tokened `Active` request must atomically select one composite identity and acquire a short-lived generation-admission pin. It then opens only the handles its route declares and transfers custody to the completed read view. An in-flight request must not lose its selected generation to retention. Explicit pinned and token-bound selectors retain their exact identity and stale-token refusal behavior.
2. Treat retained logical artifact bytes, filesystem free/allocated bytes, and transient build/merge bytes as distinct resource measures. Apply bounded write admission and backpressure before and during builds; never reclaim active, rollback-required, or live-reader artifacts to satisfy a limit.
3. Measure the complete indexing critical path before changing commit, merge, provider, or dispatch policy. Remove process-wide ingest serialization only if a source-bound multi-pair workload shows it is material, and only after durable operation ownership and resource admission cover concurrent jobs.
4. Keep generation-level immutable publication. Do not add a document-level WAL or acknowledge asynchronous ingestion until a document-visibility SLA and a durable source-spooling/replay contract require them.

These are proposed amendments to accepted [SEP-21-002](../adr/SEP-21-002-durable-authority-and-operation-lifecycle.md), [SEP-21-003](../adr/SEP-21-003-read-view-continuation-and-provider-policy.md), and [SEP-27-005](../adr/SEP-27-005-catalog-recovery-supervision-and-proof-custody.md). The implementation change must update those authorities and their decision registry together. It must not create a second live authority or a parallel internal IR.

## External design evidence and limits

- Lucene's [`SearcherManager`](https://lucene.apache.org/core/10_5_1/core/org/apache/lucene/search/SearcherManager.html) acquires/releases reader references and keeps old readers alive until users finish. Its [`SnapshotDeletionPolicy`](https://lucene.apache.org/core/10_3_2/core/org/apache/lucene/index/SnapshotDeletionPolicy.html) retains commit files while snapshotted and warns about extra disk use. The applicable principle is a request-scoped immutable read lease with measured resource cost, not a requirement to port Lucene's classes.
- [Tantivy `IndexWriter`](https://docs.rs/tantivy/latest/tantivy/indexer/struct.IndexWriter.html) uses worker buffers, blocking commits, and merges. Quanta pins Tantivy 0.22.1; newer API documentation is architectural context, not proof that a new API exists in the pinned build. The existing writer and seal calls are the direct local evidence.
- [RocksDB write stalls](https://github.com/facebook/rocksdb/wiki/Write-Stalls) explain backpressure when flush/compaction cannot keep up; [Vespa feed blocking](https://docs.vespa.ai/en/writing/feed-block.html) and [Elasticsearch disk watermarks](https://www.elastic.co/docs/reference/elasticsearch/configuration-reference/cluster-level-shard-allocation-routing-settings) demonstrate explicit write refusal under resource pressure. They do not imply that a `statvfs` check can reserve disk against unrelated writers.
- [Vespa Proton](https://docs.vespa.ai/en/content/proton.html) uses a transaction log for acknowledged document-level visibility. Quanta currently publishes complete source-bound generations; adopting that write model without a document-level freshness requirement would add a second recovery protocol.

## Target serving protocol

Define one catalog-derived active *head* per pair and a short-lived `ActiveGenerationAdmissionPin` created with the head read under one small pair-local synchronization point. The head contains composite generation, activation token, and manifest/source commitments; it does **not** retain opened snapshot handles for the lifetime of the pair. The pin protects the selected generation's ledger admission, auxiliary authority needed by declared domains, and physical track namespaces only until the request has acquired its read view. Existing registry handles then protect the route's actual opened artifacts through execution. Auxiliary epochs keep their declared rules in `QueryReadViewV2`; the head must not freeze an unrelated auxiliary epoch.

1. **Prepare:** seal both tracks, verify source and model commitments, open/prove the candidate handles under the existing snapshot registries, then release those proof handles according to registry policy. Form a candidate head. No active head changes.
2. **Commit:** perform the existing durable activation CAS. On failure, discard the candidate and keep the old head. If durability or publication is uncertain after the durable write, fence new `Active` reads until recovery reconstructs the head from verified durable catalog state; never infer success from the in-memory head.
3. **Publish:** after the durable commit, atomically replace the catalog-derived pair head and then return the activation ACK. Head replacement and request admission-pin increment share a short synchronization point. A query admitted before replacement may complete on the old generation; every query admitted after ACK obtains the new one. A query overlapping replacement obtains one complete composite, never a mixed lexical/semantic pair.
4. **Read:** un-tokened `Active` obtains the head and pin together, constructs `QueryReadViewV2` by acquiring only declared domains, and drops the admission pin after the view owns its evidence and opened handles. On view-construction error, cancellation, or deadline, drop the pin. A token-bound `ResolvedActive` must still refuse a changed token; it cannot silently move to a new generation. Pinned historical requests keep their exact-generation admission rule.
5. **Retire:** the retention planner and authority/ledger pruning must observe outstanding admission pins under the same synchronization rule as head replacement. A pinned generation cannot lose its required authority or physical namespace before view assembly. Once pins drain, a subsequent pass may reap. Existing snapshot registry holder tracking continues to defer physical deletion for completed views. Report pin count, oldest pin age, deferred bytes, and ingest stalls; bound admission with existing query capacity and release on cancellation. Restart reconstructs heads only from the verified durable catalog and physical pair.
6. **Rollback and quarantine:** use the same prepare/commit/publish rule for rollback. Proven active corruption or durable invalidation fences new admission immediately and follows the typed fail-closed/quarantine contract; an independently cached old head cannot continue serving.

The select/pin and head-replacement critical sections contain no provider call, disk hashing, or native open. Queries do not hold the pair mutation mutex during physical open or execution. If the catalog/ledger boundary cannot make the select/pin and retention check atomic, amend that boundary with its producers and consumers rather than adding a retry around `UNKNOWN_GENERATION`. The design must be tested with active-pair cardinality above the snapshot cache limit: active heads alone must not pin one lexical and semantic handle per pair.

**Alternatives rejected:** a single bounded retry of `Active` can still lose another generation under repeated transitions and can hide a stale token; holding the pair mutex through read-view open makes query tail latency depend on activation proof; a full mutable WAL/LSM serving rewrite is unnecessary for complete-generation publication.

## Target ingest and resource protocol

### Resource accounting

Publish distinct metrics and limits for `retained_logical_bytes`, filesystem available bytes, estimated allocated bytes, live staging/backup bytes, merge/ANN temporary bytes, live-reader-pinned bytes, process RSS, and declared buffer charges. Deduplicate hard links for logical retention; do not present `metadata.len()` as allocated disk usage. Filesystem clone/compression accounting may remain approximate, so strict per-root physical quotas require an OS/filesystem quota or isolated volume.

Before a build, reserve a conservative per-job transient budget and require free-space headroom. Recheck during mutation and stop new writes at high/critical watermarks; return a typed resource refusal while keeping the old active pair. Backpressure must account for deferred GC and old reader leases. It must not force-delete an active or rollback-required generation. Provider, seal hashing, ANN training, and merge work share bounded CPU/I/O/memory permits; queries have separately reserved capacity. Report admission stalls and achieved, not just offered, ingest throughput. Process RSS is a pressure signal; without an OS-enforced memory boundary, the application must not call this a hard process-memory cap.

### Work scheduling and acknowledgement

Keep the current synchronous terminal receipt until measured multi-pair contention justifies an async job API. If adopted, one operation journal/catalog remains authoritative. An `Accepted(job_id)` response requires the source bytes or immutable source reference and the job claim to be durable and replayable. `Sealed`, `Ready`, and `Active` are distinct observed milestones; `wait=active` is an explicit completion option. A transient in-memory queue may report `QueuedVolatile`, not durable acceptance. Same-pair mutations remain serialized; different pairs may build concurrently only under resource permits. The global catalog commit and state-root retention mutation remain short, serialized authority steps.

### Storage tuning

First attribute elapsed time to provider, semantic window deletion/append, membership append, ANN seal, lexical preflight, writer commit, merge wait, seal hashing, authority commit, activation, and GC. Include actual bytes read/written and peak RSS/free space. If membership scope commits dominate, batch their records by admitted window without changing membership authority. If lexical merge wait dominates, test a bounded segment policy or publish an immutable uncompacted generation and compact into a **new** generation; never mutate an already sealed generation behind its manifest. If authenticated base scans dominate small deltas, build a pinned base proof capability that preserves both pre-intent and under-lock mutation refusal.

Do not switch sealed lexical reads back to mmap solely for speed: the current descriptor-anchored copy path intentionally avoids a process-fatal fault if an external process truncates a mapped file. A bounded page cache or mmap requires an independently proved immutable-file custody boundary and physical RSS/latency measurements.

## Adversarial decision rules

| Proposed change | Evidence that authorizes it | Evidence that stops it |
| --- | --- | --- |
| Active admission pin | A deterministic baseline G1 reap produces a transition-induced refusal after an un-tokened Active selection, with no existing guard holding G1 authority. | The forced interleaving cannot reap G1 because an existing guard already pins the selection; document that guard and add its regression instead. |
| Disk headroom and write backpressure | Logical-length accounting omits physical/transient pressure by construction; a controlled low-space or stalled-merge test shows the old active pair survives typed write refusal. | Calling the estimate a hard quota without filesystem enforcement, or allowing a write-pressure path to delete a live reader's/rollback generation. |
| Membership batching, merge policy, or base-proof reuse | One stage dominates repeated wall/CPU/I/O attribution on the pinned workload, and the candidate change improves that stage and end-to-end ingest without violating source identity, crash recovery, read tail, or disk headroom. | Provider time dominates; the gain disappears end to end; query p99, space amplification, or coverage proof regresses. |
| Concurrent or async ingest | Multiple independent pairs spend material time waiting at the process-wide ingest slot and resource permits plus durable operation ownership are proved. Durable async acceptance additionally has replayable source custody. | One-pair gin time is the only evidence, or an in-memory queue is acknowledged as durable. |
| Document-level WAL or NRT serving | A product requirement sets document-level visibility/acknowledgement latency that complete-generation publication cannot meet, with recovery and compaction budgets. | Only generation-level activation is required; an extra log would duplicate authority and add a second recovery path. |

The production contract has three independent outcomes: a query admitted on `Active` uses one complete generation even during publication and retention; resource pressure rejects or slows mutation while preserving the previous active generation; a measured change improves its predeclared indexing target without breaking read latency or retrieval correctness. Upstream engines provide design patterns, not evidence that Quanta currently meets these outcomes.

Implementation order: G0 measurement and G1 red reproduction; if G1 reproduces, admission-pin cutover and G1/G2; resource accounting/admission and G3; targeted storage optimization; optional concurrent/async ingest only after measured need and durable-source design; G4 and separate release proof. If G1 is disproved by a hidden guard, keep the existing read-view design and document the guard instead. Stop any optimization that changes source/model/chunk/index/result contracts without a fresh quality comparison.

Implementation owners: `search_corpus_lifecycle.rs` and `readiness/activation_catalog.rs` for durable activation and head publication; `query_dispatcher/selection.rs` and `query_dispatcher/read_view/view.rs` for select/pin and domain evidence; `snapshot_registry.rs` and `readiness/search_corpus_history.rs` for pin-aware retirement; `ingest_dispatcher/search_corpus.rs`, `quanta-index-ipc/src/admission.rs`, and the searchd runtime for admission/phase timing; lexical writer and semantic build owners for measured storage changes. Extend the existing `CS-BENCH-04` producer/qualification rail rather than creating an unregistered performance harness. If a persisted or wire format changes, provide an explicit offline rebuild or migration decision and reject old formats at the new runtime boundary; do not add a silent dual live decoder.
