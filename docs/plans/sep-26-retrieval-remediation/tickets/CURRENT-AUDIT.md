## 우선순위와 종결 순서

1. **P1 — 증거 고정:** Semble phase-metrics seam은 동시 수정 중 8개 fixture 실패를 낳았지만, 이후 local contract 전체는 통과했다. 이제 소스/dirty owner를 고정하고 Rust/SDK exact inventory 및 clean-source contract/SDK receipt를 재발급한다. moving checkout의 local pass를 pair 자격 증거로 쓰지 않는다.
2. **P1 — 구현 공백:** RBR-04의 unsupported 파일 coverage authority; RBR-06의 세 span과 지표; RBR-01의 서버 내부 timing/overhead; RBR-10의 계측 공개 경로. 먼저 독립 expected fixture, 이어 producer→schema→replay→negative mutation을 한 단위로 변경한다.
3. **P1 — 현 소스 재자격:** RBR-02/03/04/05/07/11의 owning pinned comparator/Rust/daemon/asset rails를 정확한 revision·의존성으로 재실행한다. Python 집중 통과를 SDK/semantic 통합으로 승격하지 않는다. RBR-11 legacy `ps`의 PID 재사용 identity 미결합은 qualified owner proof가 아닌 한계로 유지한다.
4. **P2 — 조건부 결정:** RBR-08 진입 probe, RBR-09/10 개발 실험에서 효과가 없거나 CI가 불명확하면 기본값 유지로 닫는다. 측정 전 정책 변경 금지.
5. **P1 — RBR-12 custody 및 조건부 proof 구현:** 현 `validate_suite`는 단일 suite만 받으며 `suite.schema.json` split은 train/eval뿐이다. 서로 다른 development·holdout suite의 같은 파일/정의/질의 가족 누수를 검증하는 frozen experiment manifest와 cross-suite validator가 필요하다. T15/T16은 임의 `pass` JSON이 아니라 원본 vector/증분 row-set·execution receipt·source/model/dependency identity로 재도출해야 한다. 기존 v3 역사 artifact의 의미를 몰래 바꾸지 말고 새 admission 경계를 명시한다.
6. **외부 자격:** RBR-12의 독립 gold·admission·frozen 외부 corpus/model·quiet host가 준비된 경우에만 최종 holdout 한 번과 fresh-process replay를 수행한다. 준비되지 않았으면 개발 구현과 별개로 `NOT_RUN`을 유지한다.

## 종결 금지선

과거 `just retrieval-contract-local`과 Python 전체 suite는 당시 local diagnostic으로 exit 0이었지만 현 HEAD clean-source proof가 아니다. `benchmark-prep-local`, clean-source contract/SDK receipts, live pair 및 성능 검증은 이번 재감사에서 `VERIFIED`가 아니다. 특히 현재 dirty 작업 트리를 clean으로 꾸미거나, 과거 HEAD의 receipt를 재활용하거나, test count·PASS 문자열만으로 qualified를 선언하지 않는다.
