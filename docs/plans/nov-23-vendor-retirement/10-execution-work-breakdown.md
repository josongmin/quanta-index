## 5. 원래 엔진 후속 작업과 통합 순서

2. **Source V2 DELTA [08](08-engine-source-delta.md):** S `quanta-runtime/.../original_successor_v11.rs`의 미게시 target 발급 → `quanta-sdk-session-backend-owner/.../{source_tree_manifest_v4.rs,original_full_source_input_v3/source_tree_index_v2.rs}`의 prepare/commit 결속 → SDK `facts_public_source_preparation_v11.rs`, `runtime_disk_state_attribution_request_v1.rs`, `original_source_successor_v11.rs` 순으로 연결한다. Q `quanta-index-kernel/src/{source.rs,update.rs}`와 protocol/UDS는 실제 재현된 owner edit·replay 결함에 한해 수정한다. warm 단일 변경의 무관 본문 read/copy/hash/write 0 B와 FULL parity를 같은 operation에서 검증한다.
3. **검색·출하 [09](09-engine-query-and-release.md):** 동일 view의 lexical·dense 후보와 독립 정답을 먼저 캡처한다. 정답이 후보에 없으면 `crates/quanta-index-semantic/src/native/embedding/ann_query.rs`, 융합에서 밀리면 `crates/quanta-index-contract/src/native_protocol/read_session/ranking.rs`와 `quanta-index-searchd-runtime/src/native_semantic_result/hybrid.rs`, 지연이면 `native_read_session_transport/hybrid.rs`의 실제 원인을 수정한다. holdout·E07·signed Q/S SDK/CLI 설치는 각각 별도 수용한다.
4. **최종 합류 [05](05-integration-and-release.md):** Q/S source·lock·features·실행 바이너리·설치 Root를 하나의 후보로 고정하고 13개 로컬 사본 및 source reference 0을 확인한다. 구 Root reopen, 새 게시, old/new wire, pin/FD 회수, crash 복구, 품질·성능 및 rollback frontier를 같은 후보에서 실행한다. 부분 전환·단위 테스트 성공은 최종 퇴역 완료가 아니다.

각 트랙의 구현·실행 후 소유 티켓에 변경 파일, 정확한 명령, 실행된 본문과 결과, 미실행 항목을 갱신한다. **FAILED**는 실제 실패, **BLOCKED**는 필수 외부 입력 부재, **NOT_RUN**은 미실행이다. 공용 Cargo 실행은 현재 소유 레인의 종료와 자원 입장을 확인하고 직렬화한다.
