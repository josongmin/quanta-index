# 08 · Source V2 DELTA의 Q/S 제품 연결

2026년 11월 23일 기준 **NOT_RUN**. 외부 라이브러리 포크 퇴역과 독립인 Source 증분 게시 작업을 파일별로 배치한다. 현행 결과와 원래 소유 범위는 [INC-01](../../bugbash/nov-20-native-delta-cost/tickets/INC-01-source-closure.md), [INC-03](../../bugbash/nov-20-native-delta-cost/tickets/INC-03-product-acceptance.md)에 기록한다. 아래 S 경로의 기준은 `semantica-codegraph-v2/packages/analysis/quanta-v2/crates/`다.

## 현재 구현과 빠진 연결

- **이미 있음:** Store V4가 인증된 committed C1 base와 `OrderedMutationMemberV1` 변경 행으로 V2 트리를 stage한다. [`source_tree_manifest_v4.rs`](../../../../semantica-codegraph-v2/packages/analysis/quanta-v2/crates/quanta-sdk-session-backend-owner/src/durable_normal_source_attribution_generation_store_v1/source_tree_manifest_v4.rs)의 `prepare_transition_generation_with_retained_source_tree_v4` → `prepare_transition_generation_with_ordered_base_v4`와 `try_commit_changed_source_tree_participant_internal_v4`가 준비·커밋 경계다. [`source_tree_index_v2.rs`](../../../../semantica-codegraph-v2/packages/analysis/quanta-v2/crates/quanta-sdk-session-backend-owner/src/durable_normal_source_attribution_generation_store_v1/original_full_source_input_v3/source_tree_index_v2.rs)의 `try_stage_prepared_original_delta_v2`가 Runtime staging을 호출한다. Native replay는 두 committed holder를 인증하고 V2 receipt를 발급한다. [SDK 공급](../../../../semantica-codegraph-v2/packages/analysis/quanta-v2/crates/quanta-sdk-runtime-executor/src/client/mutation_api/native_source_delta_commitment_v2.rs) · [Store receipt](../../../../semantica-codegraph-v2/packages/analysis/quanta-v2/crates/quanta-sdk-session-backend-owner/src/durable_normal_source_attribution_generation_store_v1/source_transition_replay_receipt_v2.rs)
- **빠진 연결:** Runtime [`original_successor_v11.rs`](../../../../semantica-codegraph-v2/packages/analysis/quanta-v2/crates/quanta-runtime/src/orchestration/generation_source_closure/closure/original_successor_v11.rs)의 `stage_successor_from_prepared_original_v2`는 V1 target pin을 입력받아 V2 변경 행을 적용한다. Facts·disk SDK는 `prepare_original_source_closure_pair_v11`의 V1 target digest를 사용한다. Source CAS **전** 소비할 미게시 V2 target, CAS **후** manifest에 결속한 committed seal, 재시작 시 이 둘의 구별이 호출 계약으로 이어지지 않았다. 처음부터 target V2를 발급했다고 간주하면 현재 V1 전체 방문 비용과 정확한 실패 시점을 숨긴다.
- **남은 비용:** V4 준비와 participant commit의 FULL preflight는 target census·V2 본문을 읽는다. legacy V1/V3 혼합 인덱스의 별도 V1 본문 검사, V1 target·predecessor 수화, revision 발급도 남아 있다. Source CAS 전후의 손상·foreign holder 거절을 유지하면서 이 비용을 줄여야 한다. 기존 Store exact 회귀 1/1 및 Wire 13/13은 해당 동결 입력의 단위 결과이며 warm 제품 0 B 증거가 아니다.

## 검증: 순서, 입력, 합격선

1. **좁은 단위 실행.** 기존 QBC에서 S `source_commitment_v2::tests` 13개, Store `original_source_tree_node_v2_reopens_typed_members_and_branches_v3`, `original_source_successor_v11::tests` 5개와 관련 pin/inventory 회귀를 **변경된 동일 S/Q 코호트**로 재실행한다. Wire·Store의 이전 동결 통과는 현행 후보로 자동 승격하지 않는다. Q의 [`native_source_resync.rs`](../../../crates/quanta-index-kernel/tests/native_source_resync.rs)와 page/replay 회귀도 변경한 Q 함수에 맞춰 선택 실행한다. 명령은 [Justfile](../../../Justfile)·[`scripts/cargow`](../../../scripts/cargow) 및 기존 QBC 레인을 사용한다. 컴파일 실패·입장 거절·본문 실패를 각각 구별한다.
2. **절단과 멱등성.** [`ifx150_restart_recovery_product_owner.rs`](../../../../semantica-codegraph-v2/packages/analysis/quanta-v2/crates/quanta-sdk-runtime-executor/tests/ifx150_restart_recovery_product_owner.rs)의 `native_delta_rearms_same_bound_attempt_before_v9_or_carrier_v3`, `native_delta_recovers_pending_carrier_before_writer_markers_v3`, `native_delta_resumes_after_durable_q_mutation_prefix_multipage_v3`, `native_delta_restages_after_q_page_ack_before_s_progress_v3`, `native_delta_recovers_q_seal_before_s_receipt_v3`를 현행 signed Q 서버·V39 SQL worker와 실행한다. 첫 부팅, 128→129개 다중 페이지, page ACK 유실, seal 영속 직후 응답 유실, fence 변경, binding 전후 절단을 포함한다. 같은 attempt·operation·prefix/root, Source CAS 1회, V9 ACK 1개, Q Submit과 History 참조, 최신 Source 검색을 관측한다. 결속 전 절단에서는 Submit 0회를 요구한다.
3. **기능 동등성.** 실제 Java FULL 기준 세대 → 첫 V2 DELTA에서 한 파일 교체, 추가, 삭제, rename, no-op과 독립 FULL 재구축을 비교한다. 동일 published view의 Source/Path/Text와 독립 Graph의 결과, manifest/root/owner, SDK·Watch 반환과 재시작 조회를 대조한다. 손상된 V1/V2 CAS·receipt, foreign Store/repository, 취소, 중간 실패에서는 잘못된 공개와 HEAD 이동이 0건이어야 한다. RepoMap 자체를 검사하는 기존 INC-01 G2 단언은 [RepoMap 퇴역 계획](../nov-23-repomap-retirement/README.md)의 새 출하 후보에서 Source/독립 Graph 검색으로 바꾸고, 이전 `Required` root 복구는 그 계획의 이전 실행물 검증으로 남긴다. RepoMap 제거를 Source DELTA 성공의 선행 조건으로 삼지 않는다.
4. **비용과 운영.** [단일 편집 계측](../../../../semantica-codegraph-v2/packages/analysis/quanta-v2/crates/quanta-sdk-runtime-executor/src/client/ifx150_restart_recovery_test_support_v1/native_initial_full_recovery_v3/native_checked_delta_v3/single_edit_cost_v3.rs)에 현재 staging/CAS 바이트 외 pin 경로 복사, V1 digest, revision, V4 census 및 준비·commit 각 본문 read/copy/hash/write, 경로·node 방문을 같은 operation으로 귀속한다. warm 한 파일 편집에서 **전체 경로 열거 0회, 무관 본문 read/copy/hash/write 각 0 B**와 독립 FULL parity가 모두 관측되어야 한다. 계측 누락은 성공으로 보지 않는다. 현행 V4 무관 본문 재검사가 남은 동안 0 B는 미충족으로 기록하고, 불변 CAS custody를 확보하지 못하면 안전한 검사를 유지한 채 비용 목표를 미달로 보고한다. cold 최초 구축·복원 비용은 별도다.

**인수 상태:** 이 계획의 새 실행은 `NOT_RUN`. 기존 단위 동결 결과는 [INC-01](../../bugbash/nov-20-native-delta-cost/tickets/INC-01-source-closure.md)에, 설치 SDK·Watch 및 비용 결과는 [INC-03](../../bugbash/nov-20-native-delta-cost/tickets/INC-03-product-acceptance.md)에 기록한다. 최종 포크 퇴역 후보의 동일 source, feature, lockfile, Q/S 설치 바이너리와 게시 결과는 [05 통합](05-integration-and-release.md)에 인수한다.
