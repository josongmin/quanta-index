# 03 · Lance 파일 I/O와 ANN 포크 퇴역

상태 **진행 중**. Q Semantic·Runtime 소유자가 `lance`, `lance-io`, `object_store`, `lancedb`의 레지스트리 버전을 한 의존성 그래프로 맞춘다. 제품 수용에는 [02](02-sqlite-and-storage-limits.md)의 Root 단위 물리 한도를 사용한다.

### 11월 23일 순정 API 선행 확인

레지스트리의 `lance-io 7.0.0` 아카이브에서 `ObjectStore.inner`는 공개 필드이고 `ObjectStoreProvider`와 registry `insert`도 공개다. 현재 Native의 `AdmittedMemoryProvider`를 순정 공개 API로 연결할 가능성이 있다. 실제 제품 컴파일·bounded store 동작은 **NOT_RUN**이다. 순정 `lance 7.0.0`에는 `CachedIndexReaders`의 cache 보관이 남아 있고, 순정 `lancedb 0.30.0` manifest는 `tokenizer-lindera`를 지정한다. 버전만 바꿔 세 경계를 모두 보존했다고 가정하지 않는다. [현 조립](../../../crates/quanta-index-semantic/src/native/ann_session.rs) · [기존 IVF 수정](../../../vendor/lance-7.0.0/QUANTA-PATCHES.md)

후보 선별: crates.io 공식 아카이브와 레지스트리 checksum 정적 확인에서 `lance 10.0.0`의 IVF v2 `open_reader_cached`는 파일을 다시 열고 store-free 파일 metadata를 cache에 저장한다. 12.0.0과 14.0.2에도 같은 이름의 경로가 있다. 이는 7.0.0의 `CachedIndexReaders`를 직접 cache에 저장하던 경로와 다르므로 10.0.0을 FD 회수 실험의 우선 후보로 삼는다. 정적 코드만으로 전체 참조 경로나 실제 FD 회수를 확정하지 않는다. `lancedb 0.30.0`, `0.33.0`, `0.37.1`, `0.41.0` 공식 manifest는 모두 `tokenizer-lindera`를 직접 켠다. 0.41.0은 Rust 1.94·Lance 14.0.2·object_store 0.14를 요구하며 현재 [고정 Rust 1.92](../../../rust-toolchain.toml)와 다르다. 0.37.1은 Rust 1.91·Lance 10.0.0·object_store 0.13을 요구한다. 버전 상승만으로 feature 문제가 해결된다고 가정하지 않고, 선택 후보의 이행 비용·toolchain·실제 FD 수명을 별도로 시험한다. [공식 Lance](https://crates.io/crates/lance/10.0.0) · [공식 LanceDB](https://crates.io/crates/lancedb/0.41.0)

**NOT_RUN**: 4개 레지스트리 패키지의 공동 빌드, 순정 Lance의 reader 회수 실험, 저장소 Root quota와 제품 4K. 현재 Semantic·Runtime 소스는 다른 변경과 공유 중이다. 공용 Cargo 빌드가 진행 중이므로 기존 소유 경계를 확인한 뒤 관련 변경을 합류한다.

### ANN-12 · exact Top-K 동점 선택 독립 준비

**현재 결과:** `search_constrained_canonical_ties`의 제품 경로를 `search.rs::run_canonical_exact_scan`으로 전환했다. 일반 `table.query()`의 필터·row ID·vector 포함 투영을 32행 출력 배치로 스트리밍하고, Lance flat KNN이 사용하는 `lance-linalg 7.0.0`의 공개 f32 cosine batch 함수를 동일하게 적용한 뒤 `search/exact_tie_heap.rs`에서 K개만 유지한다. `extract_hit_at`은 선택 행에만 전체 응답을 materialize한다. 기존 fork `exact_tie_order` 호출은 제품 소스에서 제거했다. `./scripts/cargow --lane dev-lane check -p quanta-index-semantic --locked --offline`는 제품 scan 연결 후보에서 **VERIFIED**. 그 뒤 ordinary `extract_hits`를 HEAD 원본으로 복원하고 별도 helper만 남겼으므로 최종 소스의 Cargo check는 **NOT_RUN**이다. 독립 `rustc --edition 2024 --test` heap 본문은 실패한 선택 행 materialize 시 기존 head 보존, raw f32 distance는 다르지만 `1-distance` 보고 점수가 같아지는 동점에서 저장 키가 이기는 fixture를 포함해 **VERIFIED 7/7**이다. 128개 입력의 heap 결과는 별도로 작성한 전체 정렬 oracle과 대조했다. `persisted_semantic` 제품 본문은 공유 build lock 5초 admission timeout으로 **NOT_RUN**이며, 실행 당시 Data 여유는 약 11 GiB였다. 전체 적격 스캔의 실제 scanner 메모리·기한·CPU tail·score bit·재오픈 및 순정 후보 제품 검증은 남아 있다. 현 fork는 scoring 중 NaN을 제거하고 반환된 비유한 거리만 거절하지만 새 경로는 전체 적격 행의 NaN/Inf를 모두 storage error로 거절한다. 이 실패 범위 확대는 corruption 계약으로 수용할지 별도 판정한다.

현 fork scanner는 적격 행을 필터링하고 모든 후보의 f32 `_distance`를 계산한 다음, `1.0_f32 - distance` **내림차순**, `source_repo_id`, `repo_relative_path`, `start_line`, `end_line`, `embedding_id`, `_rowid` **오름차순**으로 `SortExec::with_fetch(K)`를 수행한다. 동점 K 경계는 물리 row ID보다 저장 키가 먼저다. `search.rs::issue_and_read_back`은 이미 K개로 절단된 stream만 보므로 여기서 재정렬하면 탈락한 행을 되찾지 못한다. 현재 readback에서 반환된 행의 비유한 거리는 storage error로 거절한다. 전체 스캔으로 옮기면 최종 K 밖의 비유한 후보까지 관측하게 되므로 실패 범위도 별도로 고정해야 한다.

`QueryExecutionOptions.max_batch_length`는 출력 배치 한도이며 DataFusion 내부 prefetch와 `spawn_blocking`의 총 peak memory 보증은 아니다. 최대 dimension은 8,192이므로 배치 1개도 vector만 `batch_rows × 8,192 × 4` bytes를 차지한다. 공개 scan 경로가 일정한 memory lease/headroom 안에 들고 취소 뒤 작업이 제한 시간 내 정산된다는 계측이 필요하다. 순정 vector query를 `limit(K)` 또는 `limit(N)`으로 반복 호출하는 방식은 각각 동점 행 누락 또는 O(N) Top-K 메모리/재연산을 일으켜 수용하지 않는다. 독립 exhaustive cosine oracle은 f64 점수를 쓰므로 순서·Recall 검증에는 유용하지만 기존 f32 점수 bit 동등성의 단독 증거는 아니다.

## 대체 설계와 수용 불가능한 공백

1. **생성 범위와 용량.** 앱 소유의 작업 scope가 held work 신원·기한·취소를 검사하고, 승인된 Root 안의 private staging 디렉터리만 순정 Lance의 쓰기 URI로 준다. Root와 생성 경로는 디렉터리 FD/nofollow 기준으로 결속해 symlink, 부모 교체, 임의 file:// 우회를 거절한다. 내부 Lance I/O가 더는 callback을 거치지 않으므로 파일별 선차감·FD 소유권·syscall 직전 사전 거절은 재현할 수 없다. 02의 실제 파일시스템/볼륨 hard quota가 DB/WAL/Lance/staging 전체의 물리 상한을 집행하고 앱 예약은 backpressure다. 승인 마운트가 없으면 ANN-02는 **BLOCKED**. [02](02-sqlite-and-storage-limits.md)
2. **write → seal → publish.** 사설 staging에서 데이터·인덱스를 완성하고 writer/session 종료, 파일 및 부모 동기화, row digest·인덱스 타입/coverage·sealed manifest·파일 신원을 검증한다. 불변 generation으로 이동해 부모를 동기화한 뒤 Catalog의 예상 predecessor/coverage CAS로 공개한다. 취소·ENOSPC·종료·CAS 충돌은 이전 head를 보존한다. 재시작은 staged/retirement journal을 재생해 미공개 사본을 회수한다. Lance 자체의 version prune이나 OptimizeAction::All을 Catalog pin 대리자로 쓰지 않는다. [인덱스 봉인](../../../crates/quanta-index-semantic/src/vector_index.rs) · [파일 작업](../../../crates/quanta-index-semantic/src/qualified_fs.rs)
3. **reader·maintenance 수명.** Catalog-selected generation을 pin하고 seal·파일 신원을 검증한 뒤 read-only session을 연다. query stream과 백그라운드 작업의 종료를 확인하고 connection/session을 해제한 다음 pin을 반환한다. 마지막 pin 뒤에만 별도 retirement 작업이 rename→unlink하고 재시작 때 이어받는다. 내부 FD를 앱 ledger가 소유한다고 간주하지 말고 실제 FD·inode를 잰다. maintenance는 private staging에서 OptimizeAction::Index 후 새 파일셋 검증/CAS로 게시한다. [control reader](../../../crates/quanta-index-semantic/src/control_file.rs) · [reclaim](../../../crates/quanta-index-semantic/src/qualified_fs.rs)
4. **IVF 순환.** 순정 후보의 index open→query→stream settle→drop→재오픈을 반복해 FD와 retired generation의 기저 복귀를 잰다. 누수가 재현되면 수정된 upstream 릴리스의 도입을 우선 검증한다. 공개 cache 설정이나 세션별 재생성이 대안인지는 같은 실험 통과로만 판단한다. 내부 강한 순환은 외부 drop만으로 해결되지 않는다. 수정 릴리스/공개 API가 없고 누수가 남으면 **퇴역 차단**. 256행 이상을 임의로 exact로 낮춰 통과시키지 않는다.
5. **Native 메모리 store.** 현 AnnMemoryStore의 제출 시점 multipart 거절, freeze 후 불변성, bounded hydration, 작업 예산·취소 전파를 유지한다. 순정 provider에서 store.inner 교체가 불가능하면 앱의 object_store::ObjectStore 구현을 순정 Lance의 공개 registry/provider에 주입한다. 공개 주입 경로가 없다면 upstream 확장 또는 후보 버전 승격을 먼저 한다. 무제한 기본 메모리 store로 바꾸지 않는다. [현재 store](../../../crates/quanta-index-semantic/src/native/ann_store.rs)
6. **LanceDB feature.** 동일 버전 순정 후보에서 전체 release feature의 cargo tree -e features -i lance-index, cargo tree -i lindera, lock diff, cargo deny를 확인한다. Lindera가 무조건 활성화되면 downstream feature 설정으로 해결되지 않는다. 허용된 release 그래프라는 명시적 판정 또는 upstream feature 분리/승격이 필요하다. lock 수동 삭제는 해법이 아니다.
7. **정확 검색의 결정적 동점.** Semantic의 search_constrained_canonical_ties는 Search Plane의 semantic·hybrid 경로에서 사용된다. 순정에서 이 호출을 단순 삭제하거나 이미 Top-K로 잘린 결과만 재정렬하면 동점 후보를 복원하지 못한다. 공개 API로 가능한 대안은 필터를 적용한 모든 적격 행을 bounded stream으로 읽고, 기존과 같은 f32 cosine distance 및 보고 점수 `1.0_f32 - distance`를 계산해 (보고 점수 내림차순, source repo ID·상대 경로·시작/끝 줄·embedding ID 오름차순, row ID 오름차순) 비교자에 따른 크기 K의 heap을 유지하는 것이다. 메모리는 O(K)와 한 배치, CPU/I/O는 적격 전체 행에 비례한다. NaN·동점·필터·취소·작업 예산 및 실제 p95를 기존 독립 oracle로 대조한다. 공개 스트림으로 이 범위와 비용 계약을 지킬 수 없으면 동일 의미의 upstream API가 있는 릴리스로 승격하거나 **퇴역 차단**한다. ## 전환 순서

1. 네 순정 package의 정확한 source/feature/lock을 한 후보로 고정하고, 원본 포크와 순정 소스 차이를 위 경계별로 대조한다. 현재 표의 순정 ABI·실행 가능성은 아직 미검증이다.
2. ANN-01/03/07의 앱 어댑터를 컴파일 가능하게 만들고 ANN-02 실제 hard quota, ANN-04/05 crash·pin 수용을 통과시킨다. 승인이 없는 배포 환경에서 물리 한도를 보존했다고 주장하지 않는다.
3. ANN-06/08/09/10/12/13의 FD·포맷·품질·feature 그래프·동점 선택·read-only namespace를 닫는다. 공개 API로 bounded store를 주입할 수 없거나 IVF 누수/포맷 손실/동점 결과 차이가 남으면 포크 제거를 보류한다.
4. ANN-11과 E07를 동일 후보에서 실행한다. 과거 ANN4K PASS, 과거 제품 4K 실패, source-only compile, focused test, benchmark 완료를 현재 후보 수용으로 승격하지 않는다.
5. 위 판정 후 네 patch와 vendor 사본 및 미사용 admission API/테스트를 별도 변경으로 삭제한다. 실제 cargo metadata/lock, 보존 fixture, 제품 E2E를 다시 검사한다. 실패하면 graph 전환을 되돌리고 해당 ID에 원인을 기록한다.
