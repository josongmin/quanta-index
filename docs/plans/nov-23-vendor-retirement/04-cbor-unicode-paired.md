## 대체 구현

### CBOR

1. **CODEC-04 · 기준선.** Q IPC·SDK·replay 및 S canonical·retrieval·taint·persisted read의 envelope별 정상 CBOR bytes, old/new reader/writer 호환, malformed/trailing 값·길이·중첩·indefinite segment·긴 문자열·map key, work/메모리 거절 원인과 owner 생명주기를 기존 fixture로 분류한다. 일반 `ser/de`와 admitted 경로를 따로 판정한다. CODEC-08의 serializer/Value 전 파일을 upstream 0.2.2와 대조하고 관찰 가능한 차이별로 해당 제품 fixture 또는 비사용 근거를 남긴다.
2. **CODEC-05 · 제한된 decoder.** Q IPC의 기존 framing/length/depth preflight를 유지한다. parser **실제 backing**은 caller owner가 성장 전에 승인하고 DTO drop까지 grant를 보유하며, typed seed visitor 할당도 별도 계량한다. 제한된 wire schema에 정식 `ciborium-ll`의 token API를 사용하는 좁은 Serde seed adapter를 구현한다. Q/S 공통 사용은 의존성 순환이 없는 기존 계약 경계에 결속하고, 각 제품의 DTO·typed visitor는 각 소유자에 둔다. 선택한 version의 API와 실제 allocator 동작을 작은 호환 시험에서 먼저 확인한다.
3. **CODEC-06 · 실패 의미.** preflight claim → 한 번의 decode begin → 최종 checkpoint → complete를 유지한다. 오류·panic은 최초 원인을 덮지 않고 shared owner의 모든 clone을 poison한다. 실제 live backing의 grant는 value보다 먼저 반환하지 않는다. read work 오류는 parser semantic 오류와 구별한다. 입력 상한, scratch 최소 4 byte, 단일 CBOR value, 깊이 256, 선언 container 수 제한을 유지한다. tag/key/indefinite 형태의 새 거절은 기존 허용 fixture와 대조해 wire 호환성 결정을 요구한다.
4. **CODEC-07 · 중단 조건.** 정식 Ciborium `from_reader`를 preflight 뒤에 호출하는 것만으로 내부 parser 임시 allocation의 사전 승인·fallible birth·retained grant가 증명되지 않는다. 좁은 adapter가 기존 허용 payload와 자원 계약을 지키지 못하면 **사본 삭제 중단**. 입력 상한만 남기는 약화안은 별도 계약 변경·Q/S 승인·버전/rollout 계획이 필요하다.

### Unicode

1. **NFC-03 · 사용면 분리.** 일반 `UnicodeNormalization::nfc`, `is_nfc_quick`, `char` table 이용자와 native scratch 확장 이용자를 분리한다. Q identity의 512 byte 제한, Q lexical의 두 번 순회·출력 길이·case fold, S `InputCellUri`와 repo-relative path의 `into-DATA`·funding bank·typed refusal을 각각 매핑한다. 일반 API만 쓰는 파일은 정식 crate로 직접 바꾼다.
2. **NFC-04 · Q 소유 제한된 처리.** 기존 native 계약 경계에서 caller-owned DATA/owner를 사용한다. 정식 crate의 공개 `char::{decompose_canonical, canonical_combining_class, compose}`를 Unicode 데이터 공급자로 사용하고, 제한된 streaming 상태만 Q가 소유한다. canonical decomposition·CCC stable reorder·composition·Hangul을 Unicode 17 고정 데이터와 독립 oracle로 검증한다. 입력 byte/combining-run 상한, checked 용량 산술, 각 grow 전 work checkpoint·fallible reservation, decomposition/recomposition/sort old/new peak 동시 계량을 구현한다. 큰 run은 stable CCC counting sort 또는 동등한 bounded 알고리즘으로 처리한다. 출력 scalar와 NFC 판정은 표준 crate 및 독립 golden 양쪽에 맞춘다. 공개 API만으로 같은 기능을 구현할 수 없으면 데이터 공급원·라이선스·업데이트 책임을 재결정한다.
3. **NFC-05 · lifecycle.** `into-DATA`는 한 번만 실행, occupied output 보존, 실패 원인과 실제 backing/funding을 finisher까지 보관, backing drop 뒤 grant 해제 순서를 Q/S 타입에서 유지한다. 512 byte `InputTooLong`은 NFC=false와 구별한다. unsupported sort backing·capacity 불일치·overflow·native allocation failure를 typed 결과에 매핑한다. 정식 `.nfc()`로 caller 예산 밖 heap을 만들거나 OOM panic을 허용하지 않는다.
4. **NFC-06 · 의미 중단 조건.** 알고리즘·Unicode table version·case fold 순서 차이는 repo/path/URI identity, digest, key 정렬, lookup, persisted artifact를 바꿀 수 있다. 같은 UTF-8 입력의 Q/S ID·NFC bytes·fold bytes·ordering·hash/digest를 대조한다. 차이가 있으면 포맷·identity 변경을 승인받고 이전 실행물로 승인 데이터를 읽어 격리 Root를 이관 또는 재색인한다. 새 Q/S를 같은 권위로 절체하기 전에 기존 상태와 복구 frontier를 대조한다.
