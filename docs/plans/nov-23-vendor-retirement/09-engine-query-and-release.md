# 09 · Native 검색 품질, E07과 서명 출하 인수

상태 **NOT_RUN**. 기존 포크 상태에서 수리한 엔진을 기준선으로 잡고 포크 제거 뒤 **같은 Q/S 출하 후보**에서 검색 결과와 운영 성능을 수용한다. 검색 알고리즘의 변경 여부는 실제 후보 캡처와 독립 평가로 결정한다. 소유자는 기존 TEXT/B/F-EVAL, D, E07/E08/P11 및 Root/F이며, 원 결과는 [07 제품 수용](../nov-20-native-cutover-closeout/tickets/07-product-qualification.md), [06 퇴역](../nov-20-native-cutover-closeout/tickets/06-tantivy-retirement.md), [08 활성화](../nov-20-native-cutover-closeout/tickets/08-release-activation.md)에 기록한다. [05 통합·절체](05-integration-and-release.md)는 포크 제거의 전체 출하 경계를 유지한다.

## 먼저 확보할 실측과 기준선

1. Root/F가 Q/S revision, Cargo.lock·resolver, target/features, daemon·CLI 실행물 SHA와 실제 SDK 호출자 산출물 신원, S 빌드, 모델·config·policy, 서명 설치 세대·선택 Root·BOOT, 코퍼스·파일 universe·view를 하나의 후보로 고정한다. 변경 전 승인 baseline은 별도 보존하고 기능·입력·하드웨어가 같을 때만 성능 쌍으로 비교한다. 과거 R56 Large PASS, B ANN4K PASS, 소스 그래프 Tantivy 0은 각 당시 입력의 증거다. 최종 후보의 SDK60·Large, ANN4K+whole SDK, signed Hybrid·독립 품질·E07, 실제 release 번들과 설치는 아직 각 원장상 미수용이다. [현행 상태](../nov-20-native-cutover-closeout/tickets/README.md#기존-오너-인수와-실행) · [4K 감사](../nov-21-bugbash-source-advance-4k/00-final-audit.md)
2. F-EVAL이 먼저 실제 Native SDK의 동일 view lexical·dense·Hybrid **파일 후보 풀과 순위**를 캡처한다. 기존 `quanta-index-retrieval-bench native-file-profile`과 `benchctl run native-file-capture --require-signed-install`, `validate`, `replay <run-id>`, `holdout_review prepare-native`, `native_file_decision`을 원 프로필대로 사용한다. 캡처 전에 DEV/EVAL 분리, query pack·모델·후보 깊이·파일 universe·qrels 판정 절차를 고정하고, 심사자에게 어느 검색 경로가 반환했는지와 순위·점수를 숨긴다. [실행 계약](../../../tools/benchmark/retrieval/README.md#explicit-native-file-profile) · [SDK peer](../../../benchmarks/retrieval/src/native_file_runtime.rs) · [캡처](../../../tools/benchmark/native_file_capture.py) · [평가기](../../../tools/benchmark/retrieval/evaluator.py) · [최종 판정](../../../tools/benchmark/retrieval/native_file_decision.py)
3. TEXT는 기존 quiet-host 실행기로 Caddy·etcd SDK60의 cold Off 각 2회와 Record 각 1회, Large 4,096파일·두 PID 재시작을 인수한다. FULL ACK는 각 호출 60초 이내이고 검색·재열기·source digest가 일치해야 한다. B는 같은 Source·resolver의 **4,096×64/Q64/K10** ANN4K와 whole Product4K 각각 1/1·exit 0, Recall@10 ≥0.95(전체 및 필터 구간), 빈 적격 결과, overlay close·두 번째 재시작·pin/delete/merge/reclaim을 인수한다. 기존 Product4K의 1,200초 materialization watchdog 실패와 후속 첫 SourceAdvance 30초 실패는 현재 후보의 최초 실패 단계부터 재현·분리한다. [07.3–07.5](../nov-20-native-cutover-closeout/tickets/07-product-qualification.md#ann과-hybrid) · [B 원 실행](../nov-21-bugbash-source-advance-4k/04-product-acceptance.md)

## 검색 결과가 떨어질 때 수정할 위치

| 관측한 첫 차이 | 확인·수정할 실제 경로 | 보존할 기준 |
| --- | --- | --- |
| 정답이 lexical·dense 양쪽 풀에 없음 | F-EVAL이 같은 view·파일 universe·적격 필터·풀 해시와 독립 exact oracle을 대조한다. TEXT는 [Native text plan/execute](../../../crates/quanta-index-searchd-runtime/src/native_read_session_transport/hybrid.rs), B는 [리전 선택 `route_graph_regions`·`rank_lance_regions`, 후보 `query_lance_region`·`search_lance_regions`](../../../crates/quanta-index-semantic/src/native/embedding/ann_query.rs)을 소유한다. 적격 파일이 컷 전에 누락됐는지, region 라우팅 손실인지, 리전 내부 ANN 손실인지 나눠 해당 함수만 수정한다. | 기존 필터·source owner 인증, old-view, ANN 독립 exact Recall과 요청 예산. top-k나 탐색 폭을 늘려 회피한다면 동일 품질·지연·메모리·읽기 한도에서 다시 측정한다. |
| 정답이 풀에 있으나 Hybrid top 10에서 밀림 | [파일 결과 변환 `convert`](../../../crates/quanta-index-searchd-runtime/src/native_semantic_result/hybrid.rs)에서 lexical/dense 파일 신원·순위·중복 제거·coverage를 대조하고, 실제 출하 융합 함수인 [Contract `rank_native_hybrid_files`](../../../crates/quanta-index-contract/src/native_protocol/read_session/ranking.rs)를 독립 계산과 비교한다. 현재 규칙은 두 파일 풀의 RRF `1/(60+rank)` 합산, 점수 내림차순 뒤 owner 순서다. 일반 [Core `HybridOrchestratorPolicy::fuse_rrf_key_lanes_with_provenance`](../../../crates/quanta-index-core/src/domains/hybrid/service.rs)는 별도 호출 경로이므로 출하 파일 결과의 원인으로 단정하지 않는다. | 같은 view·파일 source 신원, lexical 단독 순위, 동점 결정성, dense-only 파일, 중복 벡터와 partial/approximate coverage 표기. 새 가중치·rerank·후보 창은 DEV에서 고정하고 독립 EVAL을 새로 받는다. |
| 결과는 맞지만 latency·비용이 초과 | [Hybrid read-session `search`](../../../crates/quanta-index-searchd-runtime/src/native_read_session_transport/hybrid.rs)의 두 reader 계획·대기·누적 Work/기한, [결과 변환](../../../crates/quanta-index-searchd-runtime/src/native_semantic_result/hybrid.rs)의 메모리, [ANN 리전 탐색](../../../crates/quanta-index-semantic/src/native/embedding/ann_query.rs)의 후보/파일 I/O와 제공자 호출을 trace·원 요청 분모로 나눈다. 후보 깊이·rerank 수·캐시를 DEV 통제 실험에서만 조정한다. | 품질 holdout, Recall, timeout·거절 포함 분모, old-view 정확성, 메모리·물리 사용량. 진단용 trace 또는 sampled max만으로 운영 peak 합격을 선언하지 않는다. |

품질 기준은 [Native DoD](../nov-12-native-cutover/DOD.md#독립-홀드아웃-실행과-판정)의 최소 답변 가능 **100질의/12저장소**, 식별자·hard negative·무정답 **각 30질의/4저장소**와 사전 산정 표본이다. 같은 세대 Native lexical 대비 파일 MRR@10 **+0.02 이상**, 저장소 단위 쌍별 95% 하한 **>0**, Recall@10 차이 95% 하한 **≥−0.01**, 식별자 MRR 차이 **≥−0.01**, 무정답 오탐 차이 **≤+0.01**을 모두 요구한다. 미판정 상위 10, 누락·timeout·부분 결과, source/view 불일치, EVAL 누출은 성공으로 채점하지 않는다. N3/N4/N5는 DEV에만 쓴다. EVAL 결과로 파라미터를 조정하면 다음 승격에는 새 독립 EVAL을 사용한다. [07.6 원 계약](../nov-20-native-cutover-closeout/tickets/07-product-qualification.md#ann과-hybrid)

## E07과 출하 인수 순서

1. 기존 E07 오너가 같은 서명 SDK/daemon에서 Mixed와 별도 HybridFile을 [원 960초 프로필](../oct-22-finalizing/E07-performance-operations.md#fixed-profiles-and-oracles)로 실행한다. 60초 warmup+900초 open-loop 50 QPS, 동시 4/대기 64, 총 ≥10,000 attempts·각 query class ≥1,000과 1초 churn을 유지한다. HybridFile 예정 요청→decoded top20 **p95≤100ms/p99≤500ms**; 원 lexical/Mixed의 ACK·freshness와 RSS≤2 GiB, scratch≤4 GiB, physical≤64 GiB, pin 해제 뒤 60초 reclaim도 각 원 SLO대로 판정한다. queue wait·deadline 위반·거절·미완료를 원 분모에 포함한다. [07.7](../nov-20-native-cutover-closeout/tickets/07-product-qualification.md#원-e07과-비교) · [E07 DoD](../oct-22-finalizing/E07-performance-operations.md#dod)
2. 기준선과 후보의 같은 기능 비교는 동일 Linux 호스트·CPU·메모리·스토리지·입력/품질에서 `AB`/`BA` 교대 **5쌍**으로 실행한다. submit→ACK와 회차별 조회 p95의 짝별 candidate/baseline 비율 중앙값은 각각 **≤1.05**다. 절대 SLO는 별도로 통과해야 한다. 결과 기능, 모델, query mix, 캐시/기한, 후보 깊이 또는 호스트 입장이 다르면 그 쌍은 자격 없는 비교다. [07.8](../nov-20-native-cutover-closeout/tickets/07-product-qualification.md#원-e07과-비교) · [승격 기준](../nov-12-native-cutover/DOD.md#이번-이전의-추가-승격-기준)
3. Root/F는 기존 06.4에서 최종 후보의 대체 **126** 본문과 유지 old-Q **2** 본문, `just rust-check-tantivy-retirement`, 실제 release target/features의 Cargo graph·compiler stream·daemon/CLI/SDK 번들 **Tantivy 0**을 인수한다. [출하 캡처 `capture_release_build`](../../../tools/ci/check-tantivy-retirement.py)와 `just rust-capture-release-build daemon|cli <외부 기록 디렉터리>`를 기존 Cargo 큐에서 사용한다. 포크 제거의 registry/lock/source-closure·동작 검사는 [05](05-integration-and-release.md)에서 함께 인수하며, 소스 graph 0을 출하 바이너리 증명으로 대체하지 않는다. [06.4/06.5](../nov-20-native-cutover-closeout/tickets/06-tantivy-retirement.md#검증) · [Justfile](../../../Justfile)
4. D/S/H는 같은 Q ELF·S 빌드·설치 세대의 서명 readback, Native 선택/root·BOOT·config/policy, 공개 SDK/CLI·CP2, History FULL/DELTA·동일 operation 재시도·두 PID 복구 **3건**과 restore-forward를 기존 03/06.5 큐에서 공급한다. F는 signed Native capture와 E07 결과를 그 설치 신원에 묶는다. 입력이 없으면 `BLOCKED`, 실행 본문 0건은 `NOT_RUN`이다. [03 설치·복구](../nov-20-native-cutover-closeout/tickets/03-signed-published-cp2.md) · [06.5](../nov-20-native-cutover-closeout/tickets/06-tantivy-retirement.md#검증)
5. E08/Root는 기존 순서 **격리 T → 통합 A·`proof-authority-code-gate` → E06 선택 CAS → 통합 B·같은 P10 ELF의 P11 caller/kernel 2건과 운영 배포·활성화·복구 → `proof-authority-final-qualification`**을 유지한다. 이미 발급된 aggregate만 검사할 때 `proof-authority-release-gate`를 사용한다. P11의 승인 Linux target·action·독립 observer·서명 키·inventory가 실제로 공급돼야 한다. 이전 Root로의 단순 복귀는 첫 durable 게시 이후 허용하지 않으며, 기존 E08 restore-forward의 old-head coverage와 선택 CAS가 통과해야 활성화한다. [08 릴리스 원장](../nov-20-native-cutover-closeout/tickets/08-release-activation.md) · [P11 등록](../../../tools/ci/proof-authority.toml) · [05 절체](05-integration-and-release.md#배포와-복구)

## RepoMap과 상태 경계

[RepoMap 퇴역](../nov-23-repomap-retirement/README.md)은 같은 S/Q 비호환 출하에서 caller·공개 SDK·wire를 제거하는 별도 구현이다. B의 Product4K fixture는 이미 Text+Semantic만 활성화하므로 RepoMap 삭제를 4K 재실행의 선행 조건으로 두지 않는다. 다만 최종 signed 후보의 API/SDK·Graph/Path/History 유지와 이전 `Required` 복구는 같은 설치·운영 판정에 들어간다. RepoMap 제거 또는 포크 제거 자체를 Hybrid 품질 개선의 증거로 계산하지 않는다.
