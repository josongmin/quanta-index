- Status: implementation plan, **not** an implementation or release receipt.

  policy-gate work below remain proposals, not implemented by that bump.

## 1. Decisions that implementations must preserve

1. One captured environment/CLI input becomes one immutable `SearchdConfig`. The `serve`, `config check` and `config show` paths use the same resolver. `config check/show` branch before `run_supervised`, umask/signal installation, state-root lease, adapter open or provider construction. `HOME` root fallback is an injected input, not an ambient read inside the pure resolver. Direct programmatic `SearchdConfig` use runs the same typed validation before state-root effects.
2. OpenAI uses the compiled `https://api.openai.com` transport. The grant's trimmed `QUANTA_INDEX_PROVIDER_ENDPOINT` must equal that exact base URL in pure config validation **and** runtime composition. It is authorization, not a route selector. No new provider-contract-ID knob, endpoint override or route-equivalence claim. The embed crate exports the one transport identity constant; the daemon must not copy its literal.
3. `EffectivePolicyDigestV1` is an explicitly enumerated typed encoding of resolved nonsecret policy, including selected built-in recipe/query names and effective model ID/revision/dimension. It excludes paths, raw endpoint, tenant, grant authorization details, credentials and runtime generation state. The diagnostic shows inclusion/exclusion and value origin separately. Hash-dev, `unavailable`, OpenAI and the concurrently added pinned `potion-code` profile each need an explicit expected-identity case. Local model path is excluded; compiled pinned model identity is included, and asset hashes are checked at boot.
4. Typed-only reuse requires search-owned origin proof for **every live semantic row**. Existing `corpus_policy_digest` and producer-controlled `render_policy_digest` cannot prove typed origin. Add internal `typed|legacy_fallback|unattested` origin per new semantic row; include it in row-root V2 and sealed manifest counts. Stamp from the derivation path, never from producer text. Direct semantic ingestion without the search-owned derivation path is `unattested`. Delta copies origin, replacements replace it and tombstones remove it. At seal, counts from the complete final table sum to `row_count`; typed-only gate accepts only `typed == row_count` and other counts zero. No external mutable receipt or per-query row scan.
5. This is a **semantic format change**, independent of the logical `index-build-v1` label: `FORMAT_VERSION` in `crates/quanta-index-semantic/src/manifest.rs` is currently 10 and must advance; the row-root algorithm gets an explicit V2 domain/version. The existing outer sealed-manifest artifact commitment is retained unless its actual file-set contract changes. No dual live decoder or in-place relabel of old rows: rebuild a candidate root. The old binary/config/root remains the pre-write rollback unit. Lexical persisted format and public ingest DTO remain unchanged unless an owner-local proof demonstrates they must change.
6. One `Arc<ResolvedGenerationPolicyV1>` is built from the resolved config and compiled identities before active-pair boot proof. Boot checks active pairs with `FullPair` evidence; query read views check only requested tracks with `DeclaredDomains` evidence on both resident hits and cold opens. The pure gate compares semantic model/revision/dimension/normalization, `semantic-source.v1` content policy and origin summary for every typed-only semantic track, lexical normalizer, and any policy-level ANN applicability. Persisted lexical format and physical ANN consistency remain adapter-open responsibilities; do not duplicate their validators in the gate. An old semantic generation is refused before query embedding/provider I/O; a lexical-only historical query does not open semantic. A policy mismatch never quarantines an intact artifact. Current query cold-open retains its sealed-layout proof level; activation/restart keep deep `open_proven` proof.
7. Boot currently proves active pairs before constructing embedders. Keep that order: project expected corpus identity from the typed profile and compiled constants, then compare it with the **single actually built** corpus provider before opening sockets. Also compare the built query embedder's advertised ID/revision to the corpus provider for every usable query profile. `DeclaredDomains` semantic evidence includes the **observed** query embedder ID/revision read from the dispatcher's provider port before I/O; the pure rule compares it to the opened seal, preserving the old query/index mismatch refusal even for test-injected embedders. OpenAI's sealed model ID is namespaced (`openai:<model>`); `unavailable` intentionally has a hash corpus identity and an unavailable query identity, so semantic query admission returns the existing provider-unavailable error without provider I/O. A local `potion-code` config check validates selection/path syntax only; boot verifies pinned model bytes. No second independently maintained model-ID mapping may silently pass if the provider identity disagrees.
8. Candidate-root qualification uses the same activation and restart paths in an isolated candidate daemon. `verify-state` is a state-format proof, not this policy gate. Do not add a second offline compatibility implementation. Source/render truth from Semantica is a producer responsibility; Quanta's origin field proves the typed input route and committed digest values, not the semantic correctness of those values.

W0 freezes profile vectors from the current owners: `crates/quanta-index-lq-text-normalizer/src/version.rs` (`TEXT_NORMALIZER_VERSION`), `crates/quanta-index-lexical/src/sealed_generation/seal.rs`, `crates/quanta-index-semantic/src/vector_index.rs` (ANN build/effort/append constants), `crates/quanta-index-core/src/domains/hybrid/service.rs` (`RRF_K`) and `crates/quanta-index-search-plane/src/query_dispatcher/dense_admission.rs`. These are **read-only by default**. A behavior-affecting change to any vector requires a new recipe/profile name and its owning tests; no V1 label may be silently reused.

## 3. Serial integration protocol

1. **I0 freeze.** Record HEAD, `git status --short`, dirty-file owner and a digest of all files in this packet. Current dirty overlaps: `Cargo.lock`, embed `lib.rs`, daemon `config.rs/runtime.rs`, query `dispatcher.rs/semantic_query.rs`, harness `artifact.rs/report.rs` and related tests. Do not bulk-stage or overwrite them. W0 fixes env inventory, JSON/exit schema, digest field list and profile/format test vectors; reject an incomplete W0 handoff.
2. **I1 config lane.** Land pure resolver, fixed endpoint check and CLI parser on its own source snapshot. Existing `serve` and offline commands must still pass. Expose one typed policy projection factory with no daemon type imported by search-plane. Confirm direct `build_runtime(SearchdConfig)` cannot bypass grant/policy validation. Tests: searchd owner, binary CLI no-effects and malformed JSON.
3. **I2 semantic format lane.** On a separate writer lease, implement origin stamping, sealed format 11 and pre-seal contract 3 together: stream header → derivation → staging schema → storage column → final live-row root/counts → sealed manifest → open evidence. Do not merge a partially written v11 generation. Verify delta and tombstone oracle, and that old sealed, staging and unsealed-contract formats are refused with a rebuild action. The format lane must not edit dirty daemon composition.
4. **I3 gate lane.** Implement pure rule and evidence trait against I2's frozen type, then wire lifecycle and read-view. Make policy required in constructors, migrate fixtures, remove duplicate post-embedding model predicate only after pre-embedding route tests pass. Keep physical corruption/quarantine and policy refusal distinct. Gate lane must not edit dirty daemon composition.
5. **I4 one integrator.** After I1/I2/I3 are stable, one writer resolves `crates/quanta-index-searchd/src/app/runtime.rs` and `crates/quanta-index-searchd/src/app/config.rs` against the in-flight PotionCode changes. The policy is built before `validate_rehydrated_active_generations_v1`, shared with promotion/dispatcher, and checked against actual corpus **and query** provider identities before sockets bind. Verify `unavailable`, hash-dev, OpenAI and pinned local model cases. Re-freeze source fingerprint after integration; earlier lane tests are not final-source qualification.
6. **I5 owner proofs.** Run focused owner tests and storage negative cases first; then the registered integration and daemon risk suites on one quiet Rust build lane. Fix the first failing owner, re-freeze and rerun affected scope. Public error changes run API/error-inventory and fuzz checks; new module/trait surface runs hexagonal/modules checks. No timing claim from a contended host or an old binary.
7. **I6 candidate cutover.** Preserve old binary/config/root and stop its writer. Build **new** root from authoritative producer replay under final binary/config; activate only after typed coverage is proven. Activate each candidate pair, stop and restart the isolated candidate daemon under final config, inspect per-repo/revision active pairs and sealed origins, then query representative lexical/semantic/hybrid routes. Capture `{binary/source, effective digest, canonical root, active pair inventory, model identity}`. Do not infer candidate readiness from `config check` or `verify-state` alone.
8. **I7 switch/rollback.** Switch only when candidate receipt, quality/cost evidence for changed quality behavior and required operator review are complete. Before new-root writes, rollback is old binary+config+root. After new-root writes, roll forward unless replay/translation has its own verified receipt; do not point the old binary at the new semantic format. Keep both roots until the stated retention/rollback window ends. No zero-downtime claim without an actual reader/writer handoff proof.

Integration stop conditions: source fingerprint drift; unowned dirty overlap; no authoritative typed-origin count; v11 row-root/count mismatch; old-format active generation or old v2 pre-seal contract/staging table in a new-binary root; model projection differs from actual corpus provider or usable query embedder differs from corpus provider; policy gate omitted at any lifecycle/read-view path; inability to replay required historical corpus; missing release env inventory; candidate restart or requested-domain query failure. A stop is reported as a blocked rollout with the exact failing file/identity, never converted into a permissive default.
