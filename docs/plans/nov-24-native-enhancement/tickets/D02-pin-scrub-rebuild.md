# D02 · Pin 정산과 손상 감사·재빌드

우선순위 **P0 운영 안전성**. 읽기 pin/GC 복구와 객체 손상 감사·재빌드는 서로 다른 완료 조건으로 판정한다. 객체 게시 장애와 서명 복구의 공용 경계는 [D01](D01-durable-recovery.md)이 소유한다.

## 현황

로컬 펌프·Layered 물리 회수와 명시적으로 선택한 exact 뷰의 재시작 가능 Source scrub은 집중 회귀를 마쳤다. Source scrub 페이지·영속 진행 모듈은 현행 Q 작업트리에 있으며 정식 합류가 남았다. 신규 구현은 Native 데몬의 감사 대상 선정·정기 실행·미검사 범위 관측과 권위 Source에서 독립 FULL을 구축해 안전하게 교체하는 복구 경로다. E07의 60초 물리 회수·디스크 기준과 서명 설치본의 재빌드 검증은 제품 실행에서 판정한다. [완료 조건](#완료-조건)

`ReadTicket::finish`는 성공 결과라도 해제 오류를 반환한다. `Drop` 재시도도 실패하면 ticket을 발급한 Catalog의 프로세스 로컬 큐로 정산 소유권 이관을 시도한다. 이관이 거절되면 프로세스 종료 후 죽은 세션 복구가 남는다. 기존 `recover_read_sessions`가 큐의 pin별 정산·보류를 처리하고 다른 pin 및 죽은 세션 복구를 계속한다. 두 차례 해제 실패 후 정상화·재시작 없는 정산과 한 pin의 지속 실패 격리는 SQLite 집중 회귀에서 `VERIFIED`다. 만료된 pin도 살아 있는 세션이면 회수를 막는다. 마지막 해제부터 E07 **60초 안 reclaimable debt 0**은 제품 측정 `NOT_RUN`이다. [ticket 인계](../../../../crates/quanta-index-kernel/src/ticket.rs#L254) · [Catalog 큐 정산](../../../../crates/quanta-index-catalog/src/native/authority/lifetime.rs#L255) · [기존 07.9 실행](../../nov-20-native-cutover-closeout/tickets/07-product-qualification.md#출하-벤치와-비교-입력)

Native는 명시적 Source member·body scrub 및 참조 뷰의 영속 격리를 제공한다. D5는 인증된 구 Text root를 `RebuildRequired`, 위조·알 수 없는 root를 `CorruptObject`로 구분하고 Reconfigure로 새 인스턴스를 만드는 로컬 Kernel 회귀를 통과했다. 제품의 자동 재빌드 트리거는 없다. 이 API와 회귀만으로 Native 정기 전수 감사나 권위 Source에서 다시 구축한 서명 설치본 복구가 입증되지는 않는다. 구 `e2e_integrity_scrub`의 주기적 scrub은 Legacy 바이너리 대상이다.
