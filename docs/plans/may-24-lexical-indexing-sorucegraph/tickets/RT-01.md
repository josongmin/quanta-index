## §1 Purpose

Land the runtime-aware metadata engine for `LQ/Runtime-1.3`:

1. catalog-backed eval of `changed:`, `stale:`, `snapshot:`, `meta.owner:`,
   `meta.service:`, `meta.layer:`, `meta.surface:` filters.
2. `affected:` / `invalidated_by:` parser-accept + typed
   `STATE_NOT_READY: SEMANTIC_DERIVATIVE_UNBUILT` gate (real eval is Wave-7
   SEM-02).
3. **`dirty:` filter** with producer-fed apply-changes packet as sole truth
   source — closes [../feature-scope.md](../feature-scope.md) §9 Q5 and unblocks `UC-RT-08`
   (pending per [../usecase.md](../usecase.md) §3).
4. **inbound mutation surface** (`apply_changes`) feeding a bounded dirty
   buffer keyed against the currently-active generation.

At wave end: `UC-RT-01..07` green in PRE-CONF; `UC-RT-08` flips
`blocked` → `ok`; RFC § Claim-Discipline §5 provable.

Out of scope: real `affected:` / `invalidated_by:` eval (Wave-7 SEM-02);
per-tenant cross-repo `dirty:` consistency beyond §4.6 scope; producer-side
working-tree probe (producer crate concern — we consume the packet only).

## §2 Background

The runtime metadata engine is **absent** (0% code per
[../implementation-plan.md](../implementation-plan.md) §2.7) across contract, core, adapter, and conformance.
The historical `quanta-index-control` SQLite plane held `bundle_delta_applied`
(T1.1) and `generation_manifest` (T1.2); both subject to G-CONTROL-LOC
([../implementation-plan.md](../implementation-plan.md) §2.3a). This ticket references "control-plane state"
abstractly until that gap closes.

### What `dirty:` means

[../rfc.md](../rfc.md) § `LQ/Runtime-1.3` enumerates `dirty:` but does not define semantics.
[../feature-scope.md](../feature-scope.md) §1.4.1 narrows: "working tree state differs from latest
indexed generation; truth source: producer working-tree probe — search-plane
consumes only when producer marks dirty".

The search-plane has **no working tree** — it queries on top of producer-
published manifest generations. So `dirty:` cannot mean "unflushed local
edits". It must mean **"docs the producer has marked dirty against the
currently-active generation via the inbound mutation channel"**.

### Q5 resolution (locked)

[../feature-scope.md](../feature-scope.md) §9 Q5 offers: (a) deprecate `dirty:`, (b) define as
producer-marked-dirty with producer-side dependency, (c) defer. This ticket
picks **(b)** and closes Q5. Rationale:

1. `UC-RT-08` is a real persona scenario (`P2` SRE) that (a) silently drops.
2. (c) defers without value; an inbound mutation channel is needed anyway for
   incremental indexing (Wave-3 LEX-04 writer coordinator), so sharing the
   channel is cheaper than two surfaces.
3. (b) keeps truth source explicit — producer is working-tree authority; search-
   plane is a typed consumer with bounded buffer and fail-closed expiry.

### Where RT-01 sits

Per RFC § Runtime metadata engine: snapshot catalog + invalidation catalog +
ownership/service/layer registry. RT-01 owns the first and third fully; the
invalidation catalog's edges exist but the semantic-derivative payload is
gated to Wave-7 SEM-02. RT-01 also adds a fourth surface — the **dirty
buffer** — not in the original RFC enumeration; this is a deliberate
addition locked in §4.6.

### Pre-decision dependencies

- Wave-4 LEX-07: history engine ships; snapshot catalog reuses LEX-07's
  per-revision generation rows for `snapshot:<name>`.
- Wave-3 LEX-04: writer coordinator ships; `apply_changes` reuses LEX-04's
  advisory lock pattern.
- Wave-0 PRE-CONTRACT-EXT: `LqQuery.lq_version` and `LexicalErrorCode` landed.
- ADR-001 candidate locked in this ticket (§4.4): inbound `apply_changes` is
  **write-coordinator gated** sharing LEX-04's advisory lock — not a parallel
  write channel.

## §4 Deliverables

### §4.1 Crate / module layout

RT-01 extends the control-plane state owner (subject to G-CONTROL-LOC; see
[../implementation-plan.md](../implementation-plan.md) §2.3a) and adds new core port
traits. Module shape:

- `<control-plane>::runtime_metadata` — snapshot catalog, ownership registry,
  invalidation catalog edges, dirty buffer.
- `quanta-index-core::domains::runtime_metadata` — port traits.
- `quanta-index-contract::runtime` — typed carriers (`SnapshotRef`,
  `MetaKey`, `ApplyChangesPacket`, `DirtyEntry`).

Allowed dependencies: `quanta-index-contract`, workspace-pinned `time` for
TTL/timestamp handling, the existing control-plane storage backend (SQLite or
its post-G-CONTROL-LOC successor).

Forbidden: producer-side I/O (no working-tree probe in this repo), direct
edges into `quanta-index-lexical` or `quanta-index-semantic`.

### §4.3 Contract surface

- `ApplyChangesPacket { producer_id, tenant_id, repo_id, generation_pin,

- `DirtyEntry { doc_identity, mutation_kind, source_byte_hash?, dirty_since }`

- `RejectedEntry { doc_identity, reason: RejectionCode }` —
  `RejectionCode ∈ { DIRTY_STALE_GEN, DIRTY_BUFFER_FULL,
  DIRTY_BAD_IDENTITY }`.
- `SnapshotRef`, `MetaKey`, `MetaValuePattern`, `DirtyScope`, `ChangedScope`,
  `StaleScope`, `AffectedScope` — typed enums per [../dsl.md](../dsl.md) §2.4.

Wire format: hand-rolled `impl serde::Serialize` / `impl serde::Deserialize`
per [../../../../CLAUDE.md](../../../../CLAUDE.md) § Build hygiene; semgrep
`rust-no-serde-derive` enforced.

### §4.4 Inbound mutation surface (IPC method)

Lock per ADR-001 candidate: the inbound `apply_changes` channel is the **same
write-coordinator gated path** as Wave-3 LEX-04, not a separate listener.

- **IPC method name**: `apply_changes` (RPC over the existing UDS listener;
  ADR-016-adjacent).
- **Method routing**: the UDS dispatcher routes
  `LqRequest::ApplyChanges(packet)` to
  `SearchPlaneRuntimeMetadataMutationPort::apply_changes`.
- **Concurrency**: every call acquires the LEX-04 writer advisory lock on
  `(repo_id, generation_pin)`; second writer fails closed with
  `EXEC_SHARD_UNAVAILABLE` per RFC § Failure and Recovery Model §
  Dual-write split-brain.
- **Authentication**: filesystem perms Phase 1 per [../feature-scope.md](../feature-scope.md) §2;
  the inbound caller is trusted-by-fs-perm. `tenant_id` is mandatory and
  enforced against the catalog ACL per RFC § Security and Authz Model.
- **Tie to ADR-001**: ADR-001 (parser-combinator vs hand-rolled recursive
  descent) is unrelated; the relevant ADR for this surface is a new
  **ADR-017 candidate** — "inbound mutation channel: write-coordinator-shared
  vs parallel listener". This spec proposes ADR-017 = shared (write-
  coordinator gated). Ratification at Wave-5 entry.

### §4.5 Truth-source rules

The runtime catalog has **mixed truth sources** per [../feature-scope.md](../feature-scope.md) §6.4
authority chain:

| Filter | Truth source | Authority |
|---|---|---|
| `changed:` | apply-changes catalog (LEX-04 `bundle_delta_applied`) + currently-active generation | control plane (read at query time) |
| `stale:` | generation catalog vs producer's latest publish timestamp | control plane |
| `snapshot:` | generation catalog state machine | control plane |
| `meta.*` | ownership/service/layer/surface registry rows | control plane |
| `affected:` | invalidation catalog (Wave-7 SEM-02 populates edges) | control plane edges; RT-01 returns `NotImplemented` |
| `invalidated_by:` | invalidation catalog edges | as above |
| `dirty:` | **inbound dirty buffer** (§4.6) | producer-fed via `apply_changes`; bounded; TTL |

No request-time producer call — RFC § Canonical Incremental Write Pipeline §
forbidden. Every runtime filter is answered from indexed catalog rows or the
in-memory dirty buffer.

### §4.6 The dirty buffer (locked)

Per Q5 resolution in §2.3:

- **Storage**: in-memory per-tenant per-repo bounded buffer in the control
  plane (subject to G-CONTROL-LOC). Persistent dirty rows live in the
  control-plane backing store under the same per-tenant scope; in-memory
  surface is a hot cache against the persistent rows. Locked: dirty buffer
  is **per-tenant per-repo** (closes the §12 open question; see Q-RT-01-SCOPE).
- **Keying**: `(tenant_id, repo_id, generation_pin, doc_identity)`.
- **Capacity cap**: configurable per tenant; default **10_000 dirty
  entries per (tenant, repo)**. Hard ceiling 100_000.
- **TTL**: configurable; **default 300 seconds**, floor 30 seconds, ceiling
  3600 seconds. Locks the proposed range in the parent prompt (60s / 300s
  candidates) to **300s default** to match a typical commit-loop latency.
  Per-entry TTL is independent: each entry expires `dirty_since + ttl`
  after which it is evicted with a typed `runtime.dirty.evicted` event.
- **Eviction policy**: on TTL expiry → typed event + remove. On capacity
  overflow → reject `apply_changes` packet with `DIRTY_BUFFER_FULL`; do
  **not** silently drop existing entries to make room.
- **Atomicity**: writes go through the LEX-04 writer advisory lock on
  `(repo_id, generation_pin)`; reads are lock-free over a generation-pinned
  snapshot.
- **Generation alignment**: every entry pins to a `generation_pin` value;
  on generation advance, old-gen entries are **not** automatically migrated
  — they are evicted and a new packet from the producer is required. This
  is the rule that makes `DIRTY_STALE_GEN` typed (§8).

### §4.7 Snapshot catalog state machine

Per RFC § Generation model + [../feature-scope.md](../feature-scope.md) §1.4.1:

- States: `prepared`, `active`, `retired`, `failed`.
- `snapshot:<name>` resolution: `name ∈ { "prepared", "active",
  "<named-historical>" }`; named historical entries persist in the
  generation catalog until the retention policy reaps them (RFC § Index
  Lifecycle § Retention).
- Unknown name → `STATE_NOT_READY: SNAPSHOT_UNKNOWN`.
- Stale name (referenced generation reaped) → `STATE_NOT_READY:
  SNAPSHOT_REAPED`.

### §4.8 Metadata namespaced filters

Per [../feature-scope.md](../feature-scope.md) §1.4.2 — QI-extensions beyond
Sourcegraph:

| Filter | Source | Lookup shape |
|---|---|---|
| `meta.owner:` | ownership registry (`team / human / service`) | exact match on `owner_id` |
| `meta.service:` | ownership registry | exact match on `service_id` |
| `meta.layer:` | ownership registry | exact match on `layer_id` |
| `meta.surface:` | ownership registry | exact match on `surface_id` |

Registry rows are populated by the producer at indexing time and validated by
the existing `BundlePolicy::validate_delta` rail (predecessor T1.1; historical
home subject to G-CONTROL-LOC). The rails treat producer-provided metadata as
input, not authority — every write is contract-validated per RFC §
Non-Negotiable Invariants §13.

### §4.9 Generation pinning

Every runtime query is generation-pinned. Per [../implementation-plan.md](../implementation-plan.md)
§5.13 DoD: `changed:` derives only from indexed apply-changes catalog (no
request-time producer query). The pin is the `BoundGenerationPin` factory
already shipped (predecessor T4.2). Cross-generation reads are forbidden;
mid-flight generation advance during a runtime query continues against the
pinned `generation_set` until query end.

## §8 Error scenarios

Typed `LexicalErrorCode` per [../dsl.md](../dsl.md) §12 and RFC § Error Code
Taxonomy. New RT-01-introduced codes (under `STATE_*` and `RUNTIME_*`
families):

| Code | When fires | Payload | Retry |
|---|---|---|---|
| `DIRTY_STALE_GEN` | `apply_changes` against a generation that is no longer active | `{packet_id, expected_gen, observed_gen}` | wait-and-retry (after generation re-sync) |
| `DIRTY_BUFFER_FULL` | packet would exceed the per-tenant-per-repo capacity cap | `{tenant_id, repo_id, cap, observed}` | wait-and-retry (after TTL or eviction) |
| `DIRTY_TTL_EXPIRED` | every entry visible to a `dirty:` query has TTL-expired | `{tenant_id, repo_id, last_packet_at}` | not retryable (call `apply_changes` first) |
| `DIRTY_BAD_IDENTITY` | `DirtyEntry.doc_identity` does not align with any manifest row | `{doc_identity, generation_pin}` | not retryable |
| `STATE_NOT_READY: SNAPSHOT_UNKNOWN` | `snapshot:<name>` not in catalog | `{name}` | not retryable (until producer publishes) |
| `STATE_NOT_READY: SNAPSHOT_REAPED` | named historical snapshot has been reaped per retention policy | `{name}` | not retryable |
| `STATE_NOT_READY: METADATA_MISSING` | ownership registry row absent for requested meta key | `{key}` | wait-and-retry (until producer publishes) |
| `STATE_NOT_READY: SEMANTIC_DERIVATIVE_UNBUILT` | `affected:` / `invalidated_by:` invoked before SEM-02 lands | `{filter, gating_ticket: "SEM-02"}` | not retryable (deferred ticket) |

Reused codes:

- `EXEC_SHARD_UNAVAILABLE` — writer-coordinator advisory lock not held by
  caller per RFC § Failure and Recovery Model § Dual-write split-brain.
- `AUTHZ_TENANT_DENY`, `AUTHZ_ACL_MISS` — RFC § Security and Authz Model;
  tenant scope enforcement on every `apply_changes` and runtime query.
- `PARSE_INVALID_FILTER_VALUE` — malformed value per [../dsl.md](../dsl.md) §2.4
  `yes-no` grammar (e.g. `dirty:maybe`).

Negative-test corpus targets:

| Anti-row | Asserted code | Source |
|---|---|---|
| apply_changes against stale generation | `DIRTY_STALE_GEN` | this spec |
| apply_changes exceeding buffer cap | `DIRTY_BUFFER_FULL` | this spec |
| query against stale buffer | `DIRTY_TTL_EXPIRED` | this spec |
| unknown snapshot name | `STATE_NOT_READY: SNAPSHOT_UNKNOWN` | this spec |
| `affected:` invoked at Wave 5 | `STATE_NOT_READY: SEMANTIC_DERIVATIVE_UNBUILT` | this spec |
| tenant-A reads tenant-B dirty buffer | `AUTHZ_TENANT_DENY` (with property test) | RFC § Security |

No silent fallback under any row above. No empty `Ok` when authority is
absent — `STATE_NOT_READY` per repo policy ([../feature-scope.md](../feature-scope.md) §1.5.2 /
repo fail-closed posture).

| Dimension | Target | Floor / cap |
|---|---|---|
| runtime metadata p99 (single-repo) | < 250 ms | n/a (Wave-5 exit) |
| `apply_changes` p99 per ≤ 100-entry packet | < 100 ms | n/a |
| dirty buffer capacity per (tenant, repo) | 10_000 default | floor 1_000 / ceiling 100_000 |
| dirty buffer TTL | 300 s default | floor 30 s / ceiling 3600 s |
| snapshot / ownership registry lookup | < 10 ms | n/a |

Memory: dirty buffer is in-memory bounded by capacity × ≤ 256 B / entry;
ownership registry is read-mostly. Criterion regression budget per
[../implementation-plan.md](../implementation-plan.md) §8.2: p99 may not increase > 5% across the wave without an ADR.

## §12 Open questions

- **Q-RT-01-SCOPE** — **closed**: dirty buffer is **per-tenant per-repo**
  (§4.6). Alternative (per-tenant single buffer) had weaker cross-repo
  isolation per RFC § Security and Authz Model. Defense-in-depth assertion
  in DoD §11 item 9.
- **Q-RT-01-TTL-DEFAULT** — locked at **300 s default**, matching commit-
  loop latency. Tunable within §9 floor / ceiling.
- **Q-RT-01-CROSS-REPO-VIEW** — single `dirty:` query may span multiple
  repos in one tenant when no `repo:` filter is given; planner unions per-
  repo buffer reads under one tenant scope. Cross-tenant union is forbidden.
- **Q-RT-01-PACKET-IDEMPOTENCE** — default: dedupe on `packet_id`; second
  submission returns the cached `ApplyChangesAck`. Confirm at impl time.
- **Q-RT-01-DELETE-SEMANTICS** — `DirtyEntry { mutation_kind: Deleted }`:
  default include with `delete_marker: true` on the candidate. Confirm
  at impl time.
- **Q-RT-01-SEM-DERIVATIVE-RAIL** — when SEM-02 lands, default per-doc-
  identity flip: entries with a built derivative return real results; the
  rest stay `NotReady`. Confirm at SEM-02 design time.
- **Q-RT-01-ADR-017** — inbound mutation channel ADR (shared vs parallel
  listener). Default: **shared** (this spec). Ratify at Wave-5 entry.
