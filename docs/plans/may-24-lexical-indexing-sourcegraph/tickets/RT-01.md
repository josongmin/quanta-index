## §1 Purpose

Land the runtime-aware metadata engine for `LQ/Runtime-1.3`:

1. catalog-backed eval of `changed:`, `stale:`, `snapshot:`, `meta.owner:`,
   `meta.service:`, `meta.layer:`, `meta.surface:` filters.
2. `affected:` / `invalidated_by:` parser-accept + typed
   `STATE_NOT_READY: SEMANTIC_DERIVATIVE_UNBUILT` gate (real eval is Wave-7
   SEM-02).
3. **`dirty:` filter** with producer-supplied `UpsertDirty` / `EvictDirty`
   channel ops as sole truth source — closes [../feature-scope.md](../feature-scope.md) §9 Q5 and
   unblocks `UC-RT-08` (pending per [../usecase.md](../usecase.md) §3).
4. **Channel-driven dirty buffer**: search-plane consumes `UpsertDirty` /
   `EvictDirty` ops via the existing lexical channel subscriber and routes
   them into a bounded in-memory buffer keyed against the currently-active
   generation. No separate inbound IPC.

At wave end: `UC-RT-01..07` green in PRE-CONF; `UC-RT-08` flips
`blocked` → `ok`; RFC § Claim-Discipline §5 provable.

Out of scope: real `affected:` / `invalidated_by:` eval (Wave-7 SEM-02);
per-tenant cross-repo `dirty:` consistency beyond §4.6 scope; producer-side
working-tree probe (producer crate concern — we consume `UpsertDirty` /
`EvictDirty` ops only); any parallel producer→search ingress path beyond
`BundleChannelPublisher::publish` (forbidden by
[../../../ssot/channel-architecture.md](../../../ssot/channel-architecture.md) §11 rule 6).

## §2 Background

The runtime metadata engine is **absent** (0% code per
[../implementation-plan.md](../implementation-plan.md) §2.7) across contract, core, adapter, and conformance.
The historical `quanta-index-control` SQLite plane held `bundle_delta_applied`
(T1.1) and `generation_manifest` (T1.2); both subject to G-CONTROL-LOC
([../implementation-plan.md](../implementation-plan.md) §2.3a). This ticket references "control-plane state"
abstractly until that gap closes.

### What `dirty:` means

[../rfc.md](../rfc.md) § `LQ/Runtime-1.3` enumerates `dirty:` but does not define semantics.
[../feature-scope.md](../feature-scope.md) §1.4.1 narrows: "working tree state differs from latest
indexed generation; truth source: producer working-tree probe — search-plane
consumes only when producer marks dirty".

The search-plane has **no working tree** — it queries on top of producer-
published manifest generations. So `dirty:` cannot mean "unflushed local
edits". It must mean **"docs the producer has marked dirty against the
currently-active generation via `UpsertDirty` channel ops, until either
explicitly cleared via `EvictDirty` or TTL-evicted by the search side"**.

### Q5 resolution (locked)

[../feature-scope.md](../feature-scope.md) §9 Q5 offers: (a) deprecate `dirty:`, (b) define as
producer-marked-dirty with producer-side dependency, (c) defer. This ticket
picks **(b)** and closes Q5. Rationale:

1. `UC-RT-08` is a real persona scenario (`P2` SRE) that (a) silently drops.
2. (c) defers without value; the existing lexical channel already carries
   incremental writes from producer→search, so reusing the channel's
   `UpsertDirty` / `EvictDirty` ops costs zero new ingress surface.
3. (b) keeps truth source explicit — producer is working-tree authority; search-
   plane is a typed consumer with bounded buffer and fail-closed expiry.

### Where RT-01 sits

Per RFC § Runtime metadata engine: snapshot catalog + invalidation catalog +
ownership/service/layer registry. RT-01 owns the first and third fully; the
invalidation catalog's edges exist but the semantic-derivative payload is
gated to Wave-7 SEM-02. RT-01 also adds a fourth surface — the **dirty
buffer** — not in the original RFC enumeration; this is a deliberate
addition locked in §4.6.

### Pre-decision dependencies

- Wave-4 LEX-07: history engine ships; snapshot catalog reuses LEX-07's
  per-revision generation rows for `snapshot:<name>`.
- Channel SSOT: `LexicalChannelOp::UpsertDirty` / `EvictDirty` ops shipped in
  [../../../ssot/channel-architecture.md](../../../ssot/channel-architecture.md) §3.1. Search-side dirty buffer is a
  pure channel-subscriber callback; no parallel ingress.
- Wave-0 PRE-CONTRACT-EXT: `LqQuery.lq_version` and `LexicalErrorCode` landed.
- No separate writer-coordinator gate: the lexical channel already serializes
  producer→search writes per
  [../../../ssot/channel-architecture.md](../../../ssot/channel-architecture.md) §5.3 dispatcher loop. Search side
  inherits monotonic seq ordering for free.

## §3 Inputs

Runtime-side inputs RT-01 must consume:

1. **`LexicalChannelOp::UpsertDirty { repo, revision, generation, doc_id,
   applied_at_ms, payload_hash: [u8;32] }`** — producer marks a doc dirty
   against the currently-active generation. Decoded by the lexical channel
   subscriber, then forwarded to `DirtyBuffer::apply`.
2. **`LexicalChannelOp::EvictDirty { repo, revision, generation, doc_id }`**
   — producer explicitly clears a previously-dirty doc. Decoded by the same
   subscriber, then forwarded to `DirtyBuffer::evict`.
3. **TTL sweep** — search-side `sweep_expired(now_ms)` worker evicts entries
   past `applied_at_ms + ttl`. TTL eviction is a search-side concern only;
   producer never emits TTL ops.
4. **LQ query carrying `dirty:` filter** — runtime engine reads the buffer
   under a `BoundGenerationPin` to answer `dirty:yes` / `dirty:no` scopes.

## §4 Deliverables

### §4.1 Crate / module layout

RT-01 adds runtime metadata state owned by the search side (subject to
G-CONTROL-LOC; see [../implementation-plan.md](../implementation-plan.md) §2.3a) plus new core port
traits. Module shape:

- `<runtime-state-owner>::runtime_metadata` — snapshot catalog, ownership
  registry, invalidation catalog edges, dirty buffer. The dirty buffer is an
  in-memory structure; persistent backing is the channel WAL replay on
  startup, per [../../../ssot/channel-architecture.md](../../../ssot/channel-architecture.md) §4.7 (crash recovery).
- `quanta-index-core::domains::runtime_metadata` — port traits + the
  `DirtyBuffer` channel-subscriber callback wiring.
- `quanta-index-contract::runtime` — typed carriers (`SnapshotRef`,
  `MetaKey`, `DirtyEntry`). `DirtyEntry` is now derived from the channel op
  payload (`UpsertDirty { doc_id, applied_at_ms, payload_hash }`); there is
  no separate `ApplyChangesPacket` envelope.

Allowed dependencies: `quanta-index-contract`, workspace-pinned `time` for
TTL/timestamp handling, the runtime-state owner's storage backend.

Forbidden: producer-side I/O (no working-tree probe in this repo); direct
edges into `quanta-index-lexical` or `quanta-index-semantic`; any
producer→search ingress channel other than `BundleChannelPublisher::publish`
([../../../ssot/channel-architecture.md](../../../ssot/channel-architecture.md) §11 rule 6).

### §4.2 Port traits in core

Land in `quanta-index-core::domains::runtime_metadata`:

```
SearchPlaneRuntimeMetadataPort
  fn resolve_changed(
      &self, scope: ChangedScope, pin: BoundGenerationPin,
  ) -> Result<DocIdentitySet, CoreError>;

  fn resolve_stale(
      &self, scope: StaleScope, pin: BoundGenerationPin,
  ) -> Result<DocIdentitySet, CoreError>;

  fn resolve_snapshot(
      &self, name: SnapshotRef,
  ) -> Result<PublishedGenerationSet, CoreError>;

  fn resolve_meta(
      &self, key: MetaKey, value: MetaValuePattern, pin: BoundGenerationPin,
  ) -> Result<DocIdentitySet, CoreError>;

  fn resolve_affected(
      &self, scope: AffectedScope, pin: BoundGenerationPin,
  ) -> Result<DocIdentitySet, CoreError>;
      // returns NotImplemented until SEM-02 lands

  fn resolve_invalidated_by(
      &self, source: DocIdentity, pin: BoundGenerationPin,
  ) -> Result<DocIdentitySet, CoreError>;
      // returns NotImplemented until SEM-02 lands

  fn resolve_dirty(
      &self, scope: DirtyScope, pin: BoundGenerationPin,
  ) -> Result<DocIdentitySet, CoreError>;
      // queries the dirty buffer; see §4.6

DirtyBuffer (channel-subscriber callback, not an IPC trait)
  fn apply(&self, entry: DirtyEntry, now_ms: u64)
      -> Result<DirtyApplyOutcome, CoreError>;
      // invoked by the channel dispatcher when LexicalChannelOp::UpsertDirty
      // is decoded. Per-call atomic. Never invoked from IPC.

  fn evict(&self, doc_id: DocIdentity)
      -> Result<Option<DirtyEntry>, CoreError>;
      // invoked by the channel dispatcher when LexicalChannelOp::EvictDirty
      // is decoded. Returns the entry that was removed, or None if absent.

  fn sweep_expired(&self, now_ms: u64)
      -> Result<Vec<DirtyEntry>, CoreError>;
      // search-side TTL worker. Emits typed `runtime.dirty.evicted` per
      // returned entry. Not driven by the channel.
```

All methods are typed-fail-closed: absent authority returns
`CoreError::NotReady`, never empty `Ok` (RFC § Non-Negotiable Invariants
§§1–3; [../feature-scope.md](../feature-scope.md) §6.4 authority chain). `DirtyBuffer::apply` /
`evict` are pure side-of-channel-dispatch callbacks — there is no
`SearchPlaneRuntimeMetadataMutationPort` IPC trait, because no IPC ingress
exists for dirty entries (forbidden by
[../../../ssot/channel-architecture.md](../../../ssot/channel-architecture.md) §11 rule 6).

### §4.3 Contract surface

Land in `quanta-index-contract::runtime` (manual serde, no `#[derive]`):

- `DirtyEntry { doc_identity, applied_at_ms, payload_hash: [u8;32],
  dirty_since }` — search-side projection of the
  `LexicalChannelOp::UpsertDirty` op payload. Manifest-aligned doc identity
  per [../feature-scope.md](../feature-scope.md) §6.1. `payload_hash` is the producer's content hash
  of the dirty doc (opaque to search; used for dedupe and observability).
- `DirtyApplyOutcome { Accepted | Rejected(DirtyRejectReason) }` —
  per-callback outcome surfaced by `DirtyBuffer::apply`. Not transported on
  any channel; observability + audit only.
- `DirtyRejectReason ∈ { DIRTY_STALE_GEN, DIRTY_BUFFER_FULL,
  DIRTY_PAYLOAD_DECODE_FAIL, DIRTY_BAD_IDENTITY }` — see §8.
- `SnapshotRef`, `MetaKey`, `MetaValuePattern`, `DirtyScope`, `ChangedScope`,
  `StaleScope`, `AffectedScope` — typed enums per [../dsl.md](../dsl.md) §2.4.

Note: there is no `ApplyChangesPacket`, no `ApplyChangesAck`, and no
`RejectedEntry` envelope. Producer batching (or per-edit emission) is the
producer's choice and surfaces on the channel as a sequence of independent
`UpsertDirty` / `EvictDirty` ops with strict seq monotonicity (per
[../../../ssot/channel-architecture.md](../../../ssot/channel-architecture.md) §4.2 frame format and §5.3 dispatcher).

Wire format: hand-rolled `impl serde::Serialize` / `impl serde::Deserialize`
per [../../../../CLAUDE.md](../../../../CLAUDE.md) § Build hygiene; semgrep
`rust-no-serde-derive` enforced.

### §4.4 Inbound mutation surface (channel-driven)

Dirty entries enter the search plane **only** as
`LexicalChannelOp::UpsertDirty` / `EvictDirty` ops on the existing lexical
channel, per [../../../ssot/channel-architecture.md](../../../ssot/channel-architecture.md) §3.1 and §11 rule 6.

- **Ingress path**: producer publishes via
  `BundleChannelPublisher::publish(LexicalChannelOp::UpsertDirty { … })` or
  `… EvictDirty { … }`. There is no other ingress.
- **Decode site**: the channel dispatcher (search-side, per
  [../../../ssot/channel-architecture.md](../../../ssot/channel-architecture.md) §5.3 loop) decodes the op, runs
  `ChannelPolicy::validate` (seq monotonicity, generation-scope), then
  invokes `DirtyBuffer::apply(entry, now_ms)` for `UpsertDirty` or
  `DirtyBuffer::evict(doc_id)` for `EvictDirty`.
- **Ordering**: the channel already serializes producer→search writes via
  monotonic seq per track ([../../../ssot/channel-architecture.md](../../../ssot/channel-architecture.md) §4.2). No
  additional writer-coordinator lock or advisory lock is needed for the
  dirty buffer; the dispatcher is single-consumer per track.
- **Authentication**: the channel is process-local and protected by
  filesystem permissions on `{state_root}/channel/lexical/` per
  [../../../ssot/channel-architecture.md](../../../ssot/channel-architecture.md) §4.1 and §8 (publisher.lock). Tenant
  scope is enforced at query time via `BoundGenerationPin`.
- **No new ADR**: the channel SSOT is authoritative; no ADR-017 is needed
  and none is proposed.

### §4.5 Truth-source rules

The runtime catalog has **mixed truth sources** per [../feature-scope.md](../feature-scope.md) §6.4
authority chain:

| Filter | Truth source | Authority |
|---|---|---|
| `changed:` | indexed channel-applied delta catalog + currently-active generation | runtime-state owner (read at query time) |
| `stale:` | generation catalog vs producer's latest publish timestamp | runtime-state owner |
| `snapshot:` | generation catalog state machine | runtime-state owner |
| `meta.*` | ownership/service/layer/surface registry rows | runtime-state owner |
| `affected:` | invalidation catalog (Wave-7 SEM-02 populates edges) | runtime-state owner edges; RT-01 returns `NotImplemented` |
| `invalidated_by:` | invalidation catalog edges | as above |
| `dirty:` | **inbound dirty buffer** (§4.6) | producer-fed via `UpsertDirty` / `EvictDirty` channel ops; bounded; TTL |

No request-time producer call — RFC § Canonical Incremental Write Pipeline §
forbidden. Every runtime filter is answered from indexed catalog rows or the
in-memory dirty buffer.

### §4.6 The dirty buffer (locked)

Per Q5 resolution in §2.3:

- **Storage**: in-memory per-tenant per-repo bounded buffer owned by the
  runtime-state owner (subject to G-CONTROL-LOC). Persistence is by channel
  WAL replay: on restart, the dispatcher re-applies `UpsertDirty` /
  `EvictDirty` ops from the consumed cursor onwards
  ([../../../ssot/channel-architecture.md](../../../ssot/channel-architecture.md) §4.7), reconstructing the buffer
  without a separate backing store. Locked: dirty buffer is **per-tenant
  per-repo** (closes the §12 open question; see Q-RT-01-SCOPE).
- **Keying**: `(tenant_id, repo_id, generation_pin, doc_identity)`.
- **Capacity cap**: configurable per tenant; default **10_000 dirty
  entries per (tenant, repo)**. Hard ceiling 100_000.
- **TTL**: configurable; **default 300 seconds**, floor 30 seconds, ceiling
  3600 seconds. Locks the proposed range in the parent prompt (60s / 300s
  candidates) to **300s default** to match a typical commit-loop latency.
  Per-entry TTL is independent: each entry expires `applied_at_ms + ttl`
  after which `sweep_expired` evicts it with a typed
  `runtime.dirty.evicted` event.
- **Eviction policy**: on TTL expiry → typed event + remove. On capacity
  overflow → `DirtyBuffer::apply` returns
  `DirtyApplyOutcome::Rejected(DIRTY_BUFFER_FULL)`; the offending
  `UpsertDirty` op is dropped from the buffer (search side) but the channel
  cursor still advances — the dispatcher does **not** silently drop existing
  entries to make room. The rejected event is logged + observable per §7.
- **Atomicity**: writes are serialized by the channel dispatcher (single
  consumer per track, monotonic seq per
  [../../../ssot/channel-architecture.md](../../../ssot/channel-architecture.md) §4.2 and §5.3); no advisory lock
  is required. Reads are lock-free over a generation-pinned snapshot.
- **Generation alignment**: every entry pins to a `generation_pin` value;
  on generation advance (Seal observed for `generation_pin + 1`), old-gen
  entries are **not** automatically migrated — they are evicted, and the
  producer must re-emit `UpsertDirty` against the new generation. This is
  the rule that makes `DIRTY_STALE_GEN` typed (§8).

### §4.7 Snapshot catalog state machine

Per RFC § Generation model + [../feature-scope.md](../feature-scope.md) §1.4.1:

- States: `prepared`, `active`, `retired`, `failed`.
- `snapshot:<name>` resolution: `name ∈ { "prepared", "active",
  "<named-historical>" }`; named historical entries persist in the
  generation catalog until the retention policy reaps them (RFC § Index
  Lifecycle § Retention).
- Unknown name → `STATE_NOT_READY: SNAPSHOT_UNKNOWN`.
- Stale name (referenced generation reaped) → `STATE_NOT_READY:
  SNAPSHOT_REAPED`.

### §4.8 Metadata namespaced filters

Per [../feature-scope.md](../feature-scope.md) §1.4.2 — QI-extensions beyond
Sourcegraph:

| Filter | Source | Lookup shape |
|---|---|---|
| `meta.owner:` | ownership registry (`team / human / service`) | exact match on `owner_id` |
| `meta.service:` | ownership registry | exact match on `service_id` |
| `meta.layer:` | ownership registry | exact match on `layer_id` |
| `meta.surface:` | ownership registry | exact match on `surface_id` |

Registry rows are populated by the producer at indexing time and validated by
the existing `BundlePolicy::validate_delta` rail (predecessor T1.1; historical
home subject to G-CONTROL-LOC). The rails treat producer-provided metadata as
input, not authority — every write is contract-validated per RFC §
Non-Negotiable Invariants §13.

### §4.9 Generation pinning

Every runtime query is generation-pinned. Per [../implementation-plan.md](../implementation-plan.md)
§5.13 DoD: `changed:` derives only from indexed apply-changes catalog (no
request-time producer query). The pin is the `BoundGenerationPin` factory
already shipped (predecessor T4.2). Cross-generation reads are forbidden;
mid-flight generation advance during a runtime query continues against the
pinned `generation_set` until query end.

### §5.5 Step 5 — channel-driven dirty buffer
Failing tests cover the dispatcher → buffer path:

- a well-formed `LexicalChannelOp::UpsertDirty` at the active gen is decoded
  by the dispatcher and routed into `DirtyBuffer::apply`; the entry becomes
  visible to a subsequent `dirty:yes` query at the same `generation_pin`.
- `LexicalChannelOp::EvictDirty` is decoded and routed into
  `DirtyBuffer::evict`; the entry disappears from a follow-up `dirty:yes`
  query at the same pin.
- `UpsertDirty` at a stale gen → `DIRTY_STALE_GEN` (buffer untouched; channel
  cursor still advances; event surfaced per §7).
- capacity overflow → `DIRTY_BUFFER_FULL` (existing entries preserved;
  offending op dropped from the buffer; event surfaced).
- malformed `UpsertDirty` payload (CBOR decode fails or
  `DirtyEntry` validation fails) → `DIRTY_PAYLOAD_DECODE_FAIL`; channel
  track is marked degraded if the CRC is intact but the payload is invalid
  beyond decode (caller observes via `ChannelError::Encoding`); see §8.
- `EvictDirty` for a `doc_id` not in the buffer → no-op `Ok(None)`; idempotent
  semantics confirmed against the channel's at-least-once delivery model.
- ordering: `UpsertDirty(doc_id=D)` followed by `EvictDirty(doc_id=D)` at the
  same gen → buffer empty afterwards; reverse order with the same seq pair
  → buffer holds the upsert (channel seq monotonicity is authority).

### §6.2 Integration

End-to-end tests across the real channel + UDS query listener:

- Channel round-trip — producer publishes `UpsertDirty` via the real lexical
  channel publisher; dispatcher decodes and routes to `DirtyBuffer::apply`;
  a subsequent `dirty:yes` LQ query over UDS observes the entry.
- `EvictDirty` round-trip — producer publishes `EvictDirty` after the
  upsert; the `dirty:yes` query no longer observes the entry.
- Generation advance mid-buffer — `Seal` op for `gen+1` evicts gen-pinned
  entries; producer must re-emit `UpsertDirty` against the new pin.
- Crash recovery — searchd restart re-replays from the persisted channel
  cursor; the dirty buffer is reconstructed without a separate ack surface
  (per [../../../ssot/channel-architecture.md](../../../ssot/channel-architecture.md) §4.7).
- Multi-snapshot query — `snapshot:active` / `prepared` / `<historical>`.

### §6.3 Conformance

`cargo test -p quanta-index-contract --test lq_conformance` walks
`UC-RT-01..08`; verdict `ok` for all 8 rows after RT-01 exit.

### §6.4 Property tests

- Snapshot state-machine: 10k random transitions → consistent state.
- Dirty buffer capacity: 1k random `UpsertDirty` / `EvictDirty` channel-op
  sequences never exceed cap.
- Planner narrowing (RFC § Non-Negotiable Invariants §11): 1k random
  query × filter sets → `filters ⊇ planned_filters`.
- Generation pinning: 10k random gen-sequences with concurrent
  `UpsertDirty` / `EvictDirty` traffic → no cross-generation row in any
  pinned query.
- Two-tenant isolation (analogous to LEX-02's `UC-EDGE-09`): tenant A's
  `UpsertDirty` ops invisible to tenant B's `dirty:` query.

Per [../implementation-plan.md](../implementation-plan.md) §8.4: producer side may be fixture-mocked when
not asserting end-to-end producer integration; `UpsertDirty` / `EvictDirty`
ingress is exercised over the **real lexical channel publisher** (no in-test
shim), and `dirty:` queries hit the real UDS listener.

## §8 Error scenarios

Typed `LexicalErrorCode` per [../dsl.md](../dsl.md) §12 and RFC § Error Code
Taxonomy. New RT-01-introduced codes (under `STATE_*` and `RUNTIME_*`
families):

| Code | When fires | Payload | Retry |
|---|---|---|---|
| `DIRTY_STALE_GEN` | `UpsertDirty` op decoded against a generation that is no longer active | `{channel_seq, expected_gen, observed_gen}` | producer re-emits with the new generation pin |
| `DIRTY_BUFFER_FULL` | accepting the `UpsertDirty` op would exceed the per-tenant-per-repo capacity cap | `{tenant_id, repo_id, cap, observed}` | wait-and-retry (after TTL or producer `EvictDirty`) |
| `DIRTY_PAYLOAD_DECODE_FAIL` | the `UpsertDirty` op body fails CBOR decode or `DirtyEntry` shape validation (CRC intact; payload malformed) | `{channel_seq, decode_error}` | not retryable (producer bug; track may be marked degraded) |
| `DIRTY_TTL_EXPIRED` | every entry visible to a `dirty:` query has TTL-expired | `{tenant_id, repo_id, last_applied_at}` | not retryable (producer must re-emit `UpsertDirty`) |
| `DIRTY_BAD_IDENTITY` | `DirtyEntry.doc_identity` does not align with any manifest row at the pinned generation | `{doc_identity, generation_pin}` | not retryable |
| `STATE_NOT_READY: SNAPSHOT_UNKNOWN` | `snapshot:<name>` not in catalog | `{name}` | not retryable (until producer publishes) |
| `STATE_NOT_READY: SNAPSHOT_REAPED` | named historical snapshot has been reaped per retention policy | `{name}` | not retryable |
| `STATE_NOT_READY: METADATA_MISSING` | ownership registry row absent for requested meta key | `{key}` | wait-and-retry (until producer publishes) |
| `STATE_NOT_READY: SEMANTIC_DERIVATIVE_UNBUILT` | `affected:` / `invalidated_by:` invoked before SEM-02 lands | `{filter, gating_ticket: "SEM-02"}` | not retryable (deferred ticket) |

Reused codes:

- `AUTHZ_TENANT_DENY`, `AUTHZ_ACL_MISS` — RFC § Security and Authz Model;
  tenant scope enforcement on every runtime query.
- `PARSE_INVALID_FILTER_VALUE` — malformed value per [../dsl.md](../dsl.md) §2.4
  `yes-no` grammar (e.g. `dirty:maybe`).
- `ChannelError::Corrupted` — propagated up from the channel layer when CRC
  mismatch precedes any decode; marks the lexical track degraded per
  [../../../ssot/channel-architecture.md](../../../ssot/channel-architecture.md) §4.6.

Negative-test corpus targets:

| Anti-row | Asserted code | Source |
|---|---|---|
| `UpsertDirty` decoded at stale generation | `DIRTY_STALE_GEN` | this spec |
| `UpsertDirty` exceeding buffer cap | `DIRTY_BUFFER_FULL` | this spec |
| `UpsertDirty` with malformed CBOR body | `DIRTY_PAYLOAD_DECODE_FAIL` | this spec |
| query against stale buffer | `DIRTY_TTL_EXPIRED` | this spec |
| unknown snapshot name | `STATE_NOT_READY: SNAPSHOT_UNKNOWN` | this spec |
| `affected:` invoked at Wave 5 | `STATE_NOT_READY: SEMANTIC_DERIVATIVE_UNBUILT` | this spec |
| tenant-A reads tenant-B dirty buffer | `AUTHZ_TENANT_DENY` (with property test) | RFC § Security |

No silent fallback under any row above. No empty `Ok` when authority is
absent — `STATE_NOT_READY` per repo policy ([../feature-scope.md](../feature-scope.md) §1.5.2 /
repo fail-closed posture).

## §12 Open questions

- **Q-RT-01-SCOPE** — **closed**: dirty buffer is **per-tenant per-repo**
  (§4.6). Alternative (per-tenant single buffer) had weaker cross-repo
  isolation per RFC § Security and Authz Model. Defense-in-depth assertion
  in DoD §11 item 9.
- **Q-RT-01-TTL-DEFAULT** — locked at **300 s default**, matching commit-
  loop latency. Tunable within §9 floor / ceiling.
- **Q-RT-01-CROSS-REPO-VIEW** — single `dirty:` query may span multiple
  repos in one tenant when no `repo:` filter is given; planner unions per-
  repo buffer reads under one tenant scope. Cross-tenant union is forbidden.
- **Q-RT-01-IDEMPOTENCE** — default: dedupe on `(channel_seq, doc_id)`;
  duplicate `UpsertDirty` ops (channel at-least-once redelivery) overwrite
  in place. Confirm at impl time.
- **Q-RT-01-SEM-DERIVATIVE-RAIL** — when SEM-02 lands, default per-doc-
  identity flip: entries with a built derivative return real results; the
  rest stay `NotReady`. Confirm at SEM-02 design time.
- **Q-RT-01-EMISSION-CADENCE** — producer's cadence for `UpsertDirty`
  emission: per-edit (every working-tree mutation) vs batched (coalesced
  per debounce window). Per-edit gives the lowest end-to-end staleness;
  batched reduces channel pressure. Default proposal: per-edit, with the
  producer free to coalesce within a 100 ms debounce. Producer handoff doc
  required.
- **Q-RT-01-SEAL-DRIVES-ACTIVE-GEN** — whether `DirtyBuffer` should subscribe
  to `LexicalChannelOp::Seal` events to automatically advance its active
  generation pin (and evict old-gen entries), or whether the runtime engine
  should poll the `LexicalGenerationLedger` at query time. Default proposal:
  auto-advance on `Seal` to avoid stale reads across a generation flip.
  Confirm at impl time.
- **Q-RT-01-EVICT-ORDER** — ordering between `EvictDirty(doc_id=D)` and a
  later `UpsertDirty(doc_id=D)` at the same generation. Channel seq
  monotonicity is authority; default: later seq wins. Confirm the producer's
  emission contract matches (an `EvictDirty` issued after a new edit must
  carry a lower channel_seq than the new `UpsertDirty`, never higher).
