## 충돌 처리

1. 현재 HEAD/dirty digest, 정확한 함수·직접 caller·변경 hunk를 대조한다. 토픽/파일명/정의 수만으로 중복을 단정하지 않는다.
2. 이미 완료된 producer와 실제 caller가 있으면 새 구현을 제거하고 필요한 영향 검증만 남긴다.
3. 같은 함수·불변식을 기존 actor가 수정하면 그 actor의 패킷으로 합류한다. 기존 Prepared proof/기존 V9·ACK·Trace transaction을 다른 lane에서 다시 만들지 않는다.
4. 서로 다른 hunk라도 공용 signature/gate/동일 oracle에 영향을 주면 P00가 ABI를 먼저 확정한다. S shared-main claim은 조율 뒤 기존 CLI의 reconcile-with로 갱신한다. 이 문서 작성에서는 claim을 바꾸지 않았다.
5. P01↔P06은 같은 기존 DELTA 담당이면 직렬이다. P05는 supplier 파일만 쓴다. terminal_handoff/custody의 소비 parent는 P06만 쓴다.
6. P03의 QE prepare/store parent, P04의 QE `constructors.rs` 구성 변경, P08 공통 trait·query별 capability·flow parent, 모든 공용 Cargo/lib/export/mount는 P00에 최소 patch로 반환한다. P04의 `transaction.rs::PersistRollbackGuardV1::new` 내부 변경은 P04가 소유한다. source-map의 읽기 후보를 수정 허용으로 해석하지 않는다.
7. 기존 query 알고리즘/decoder와 E01·PUB·FNL410·W205 source hunk는 원 담당의 범위를 유지한다. 외부 typed 입력이 없으면 해당 packet gate만 BLOCKED로 남긴다.
