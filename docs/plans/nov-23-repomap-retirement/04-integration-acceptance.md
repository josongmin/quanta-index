# 04 · 통합·검증·출하 전환

담당은 Root/F와 기존 D/E08이다. [Semantica](01-semantica.md)와 [Quanta Index](02-quanta-index.md)의 인터페이스를 같은 서명 후보에 합친다. [저장 퇴역](03-storage-retirement.md)은 활성화 수용 이후에 별도로 판정한다. 제품 본문은 **NOT_RUN**이고 기존 Native 설치의 운영 활성화는 **BLOCKED**다.

**구현 진행.** Q 작업 트리에 Native Source-only export·이전/새 Source 대조와 S 내구 origin 결속 검증을 추가했다. FD6에는 old head·new view 전체 대신 SHA commitment를 싣고 Q가 보유한 이전·후보 Catalog에서 본문을 재구성해 완료 digest를 대조한다. S durable issuer의 full binding은 유지한다. S Native export 수신·내구 origin과 후보 발행·route seal의 호출 연결이 합류했다. Q SDK·wire 제거와 S 호출자·Workset 제거가 작업 트리에 진행 중이며 S 발행·cold SDK 본문 전환과 S/Q 통합 컴파일은 미완료다. 일반 ProjectionAdvance의 퇴역 정책 차단도 구현 중이다. BOOT V2와 selection schema 3의 정책 참조 표현은 추가됐지만, Q 절체 검증기에는 보유한 이전 route의 `repomap_heads`와 후보 정책을 대조하는 코드를 추가했다. Legacy imported head는 고정 instance·projection을 공유하므로 각 head의 repo/revision 해시를 강제하지 않고 물리 profile 결속과 중복 정규화 코드로 전환했으며 Rust 실행은 **NOT_RUN**이다. 이전 물리 profile에서 정책을 추출하고 S parser·정책 intent·route seal·handoff에 전달하는 후보 코드를 추가했다. Source head가 없는 경우에는 policy-only BOOT을 사용한다. 서명된 활성화 증거와 재시작 후 입장 적용은 미완료다. Q 새 route seal 요청과 launcher schema 3 전달을 포함한 Rust 통합 실행은 **NOT_RUN**이다. 보호 Source route가 있는 경우 S 준비 중 `SealCandidateWithSourceRoutes`가 BOOT를 먼저 봉인하고 launcher의 `SelectCandidate`는 이를 재확인한다. 따라서 이전 route의 정책 확보 → S route에 정책 전달 → V2 BOOT 봉인 → handoff → 후보 선택 → FD6 순서로 연결해야 한다. 후보 선택 뒤 재봉인하면 FD6의 대상 결속이 바뀌므로 허용하지 않는다. S 신규 발행은 아직 V9 Required의 RepoMap member·digest·owner pipeline에 결속되어 있으므로 Source/History 신규 issuer와 cold SDK 본문 전환이 선행돼야 한다. 기존 prepared artifact V6은 Semantic roots 용도이므로, Source-only는 별도 V7 이상 계약에서 scope·handoff·Source witness 및 replay/ACK를 함께 정의해야 한다. 구 V5/V6의 RepoMap root와 digest 판독은 보존한다. V7 일반 계약·stored ref, Native 예산 검증·canonical materialization, DELTA issuer 조립 및 Source 정본 검사가 추가됐다. Q Native storage root와 S durable Source manifest target digest는 다른 축이므로 같은 값으로 가정하지 않는다. SDK의 인증 terminal tuple은 Native custody를 거쳐 aggregate ingress에 전달하며 Q selection snapshot과 대조하도록 추가했다. tuple 자체는 lifecycle guard나 CAS 직렬화 권한이 아니다. 기존 guard는 Source closeout에서 해제되고 SDK indexing은 이후 비동기 단계에서 시작한다. guard를 연장하면 head 잠금 수명과 잠금 순서가 바뀌므로 안전성 확인 전까지 issuer 호출은 차단한다. 같은 operation의 guard loan·최종 CAS 및 Watch의 별도 Source capability 결속은 남았다. Native decoder의 실제 본문 검증, FULL/Resync body 증거, issuer·replay·ACK 연결은 미완료다. V7 Source 점검은 기존 Source lifecycle guard를 받아 같은 경로인지 확인하도록 추가했으며 SH 재획득을 하지 않는다. 이 guard는 다른 Source CAS를 직렬화하지 않으므로 실제 발행 연결 시 최종 CAS에서 정확한 predecessor를 다시 검증해야 한다. guard 경로 검사와 기존 CAS 테스트가 변경되어 이전 lifecycle lease 인계의 16/16 동결 해시는 현 후보 증거가 아니다. FNL410의 Source CAS·historical ancestry exact 두 본문은 현재 입력에서 **0/2 NOT_RUN**이다. S 설치 E2E의 이전 Legacy head 관측은 승인된 이전 Q 실행물에 old control wire를 직접 보내도록 전환 중이며 실제 PID 본문은 미실행이다. Q contract의 old query DTO는 내부화 중이며 잔여 호출과 S/Q 통합 컴파일은 미완료다. F23 설치 회귀는 RepoMap 조회 대신 공개 Source snapshot과 검색 결과·Q view 전후 불변을 확인하도록 본문·기존 등록을 변경했지만 컴파일과 설치 실행은 **NOT_RUN**이다. Search 응답에 보유한 Source reader의 인증 snapshot을 전달하고 reader와 결과가 불일치하면 거절하도록 후보 코드를 변경했다. F23은 이 snapshot을 ACK와 대조하지만 Rust 본문과 설치 실행 전까지 결속은 미검증이다. 새 Source의 파일 revision은 content-derived 새 식별자이며 이전 revision의 복원으로 취급하지 않는다. 이 형식의 History·SDK 호환과 실제 설치 수용은 미검증이다. 이전 Native `SourceRecord.source_repo_id`가 없으면 후보 검증은 거절한다. Q 일반 `stage_sources`는 이 값을 생략할 수 있지만 S 정규 Native 생산자는 `stage_repository_sources`를 사용한다. 실제 이전 설치에서 해당 필드가 보존됐는지 확인해야 한다. S origin FD6 증거는 전체 1 MiB 한도를 유지한다. 최대 길이 repo/revision의 368 head 직렬화 크기 probe는 추가했지만 실행하지 않았고, 다른 사실과 요청이 동시에 최대일 때 전체 용량을 보장하지 않는다. 실제 대상 크기의 수용은 미검증이며 초과 시 절체를 거절한다.

Q `./scripts/cargow check -p quanta-index-contract --lib --locked --offline`은 **VERIFIED · exit 0**이었다. 이후 Source 언어·증거 계약이 변경되어 현 입력 검증은 **NOT_RUN**이다. Q SDK·CLI의 첫 check는 제거 작업 중 control binding 누락으로 **FAILED · exit 101**이었고 구조체를 복구했다. 재검사 두 번은 기존 Cargo 잠금 대기로 **NOT_RUN · exit 124**였다. `python3 tools/ci/lint/check-wire-inventory.py`는 현재 작업 트리에서 **VERIFIED · exit 0**이다. `python3 tools/ci/lint/check-test-authority.py`는 삭제된 구 테스트 경로 참조를 정리한 뒤 **VERIFIED · exit 0**이다. `python3 tools/ci/lint/check-proof-authority.py`는 삭제된 `repomap-bounded-query`를 P02A가 계속 참조해 **FAILED · exit 1**이다. P02A/P03/P11은 새 Source 소유 본문·selector를 확보한 뒤 전환해야 하며 실행 증거도 없다. 기존 S ingress 테스트의 Legacy `serve` 기반 본문은 새 Q가 그 명령을 거절하므로 이전 승인 실행물의 증거 또는 별도 Native 대체가 필요하다. S R5에는 새 Native Source·Text·File/Path의 실제 발행·조회, stale CAS 거절과 재시작 본문을 추가했으나 Rust 실행은 **NOT_RUN**이다. S Cargo.lock의 새 lexical dev dependency 반영과 고정 입력의 topology 갱신도 남았다. Q의 History retained-page 본문은 이전 Legacy 실행물의 입력을 사용하며 새 S Native History paired 본문은 미구현이다. 이전 HEAD의 Native RepoMap request 7개·response 7개 숫자 태그를 현재 선언과 정적으로 대조했을 때 재사용은 0건이다. 구 인코더의 실제 프레임과 dispatch 부작용은 미실행이다. S `python3.12 tools/testing/suite_registry_v1.py --fail-on-violation`은 기존 `quanta-cli-server`의 `wire_v2`·`parse_v3` 모듈 경로 미해결로 **FAILED · exit 1**이며, 레지스트리 YAML 파싱은 1,546건·오류 0건이며 F23 exact selector 정의 1건과 등록 참조 2건을 정적으로 대조했다. S R5 생성 topology `lint-topology-contracts.sh --regenerate`는 실행 중 `Cargo.lock`과 소스 digest가 변해 freshness 검사에서 **FAILED**했고 생성 결과는 설치되지 않았다. Python launcher의 schema 3 handoff/receipt 검사 11건과 build/prepare 검사 6건은 **VERIFIED**, Linux 전용 3건은 **NOT_RUN**이다. ## 후보와 실행 소유

- Root/F는 현재 S/Q 커밋과 승인된 overlay, Cargo lock·feature·target, Q release daemon, S 설치 역할과 SQL, 서명 프로필·선택·정책을 기존 실행 큐의 동일 입력에 결속한다. 각 영수증에 exact selector, 실제 본문 수, exit, 원 로그와 실행물 SHA를 남긴다.
- D는 이전 `Required`의 승인된 S/Q 실행물·root·선택과 새 비호환 후보를 공급한다. Root는 지원 소비자의 동시 업그레이드 또는 지원 종료를 확인한다. 이전 공개 조회·재시작은 이전 조합의 증거로 인수한다.
- E08은 기존 레지스트리에서 제품 계약의 득실을 대조한다. `p02a-repomap-compiler`는 해당 기능의 제품 지원이 종료되면 그 전용 증명으로 퇴역한다. `p11-cross-repo-cutover`의 **실제 S caller·Q 경계, 동일 P10 ELF, 릴리스 의존성**은 유지한다. RepoMap 전용 R5 selector를 교체할 때는 기존 등록부에 새 제품 경로를 실행하는 대체 본문과 증거를 연결한다. 기존 R5·F23의 RepoMap 양성은 이전 `Required`와 그 동결 후보의 복구 범위에 귀속한다.
