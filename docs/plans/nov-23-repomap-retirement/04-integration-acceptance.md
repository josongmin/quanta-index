### 합류 순서

1. **공용 입력 먼저 고정한다.** S Dirty 두 오너는 catalog/Dirty/Source identity와 signed 재생 소유를 합의하고, C-04와 D/E08은 FD6·Host·root/BOOT·선택 witness의 입출력을 확인한다. Watch·Resync·Q 공개 표면·History·proof 작성·기존 벤치/저장 준비는 이 협의와 병행한다.
2. **S/Q 제품 경로를 합친다.** 운영 catalog는 기존 signed Dirty 정산에 공급한다. 공용 ACKed DELTA 복원을 Watch V16·DELTA 선행 RecordOnly와 Resync FULL의 DELTA parent가 소비한다. 일반 SDK Apply·Rollback의 live/cold V7 합류까지 완료하고 신규 V3 Required 발급 0을 확인한다. FD6의 기존 S/Q 구현은 같은 입력으로 인수한다. Root/F가 공유 후보를 결속하고 실행 증거를 기존 QBC/Q 레인에서 한 번 인수한다.
3. **동일 후보를 실행한다.** 승인 S/Q·Cargo·설치 입력과 Linux ELF를 고정한다. 유지 SDK/구 wire·IFX150/FNL410과 기존 제품 수용을 실행하고 P09→P10→같은 P10 ELF의 P11 caller/kernel을 연결한다. 승인 action·독립 observer 아래 운영 절체와 역전환/복구를 실행한다. Source/History 보존을 확인한 뒤에만 기존 설치 활성화를 판정한다. 물리 회수는 보존이 끝난 root의 마지막 참조를 확인하고 별도로 승인한다.

인계는 변경 파일·소스/lock, consumer entrypoint, 남은 입력, exact selector와 실행물 SHA, 실제 본문 수·exit·로그로 끝낸다. 정적 확인과 rustc/Cargo·SDK·설치 결과의 범위를 표시한다. 의존성이 없어 진행 가능한 작업은 그대로 진행한다.

- **Dirty catalog 오너**는 권위 있는 현재 세대의 complete `RuntimeCatalogIngestBatch` 공급과 그 생산 회귀를 맡는다. 동일 repo/revision/generation·Source에 결속된 타입과 재개에 필요한 원 입력을 넘긴다. 기존 RuntimeMetadata 전체 사실을 공급할 권위가 없으면 호출 인터페이스와 필요한 입력을 명시한다. Dirty 변경분에서 facet·snapshot·edge를 합성하지 않는다.
