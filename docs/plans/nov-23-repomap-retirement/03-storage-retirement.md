## 선택할 이행 방식

**공유 Legacy 저널도 보존 범위에 포함한다.** `idempotency_v2`는 `RepoMapBundle`과 다른 ingest kind를 함께 저장한다. Catalog open은 미완료 행 재생 및 무결성 검사에서 저장된 kind와 terminal receipt를 읽는다. 공개 IPC의 DTO를 제거한 뒤에도 이전 root의 운영은 승인된 이전 실행물에 귀속한다. D/E08 이관 도구가 구 Catalog를 직접 열어야 한다면 해당 kind·receipt·event 디코더를 이관 범위에서 보존하거나 승인된 변환을 먼저 적용한다. 저널의 미결 상태·terminal event·유지 ingest 행을 함께 대조한다. [공유 저널](../../../crates/quanta-index-catalog/src/idempotency.rs#L62) · [RepoMap receipt 디코더](../../../crates/quanta-index-catalog/src/idempotency.rs#L254) · [Catalog 재오픈](../../../crates/quanta-index-catalog/src/open.rs#L182)

1. **새 root에 격리 후보를 준비한다.** 승인된 Source 생산자와 복구 경로로 RepoMap 없는 profile·라우팅을 검증한다. 이전 root의 실운영 교체는 [04의 기존 D/E08 절체](04-integration-acceptance.md#설치-절체와-중단-지점)에 귀속한다. SDK 테스트 통과만으로 기존 Native root의 운영 선택을 변경할 수 없다.
2. **독립 이전 root 전체 퇴역.** D/H가 실제 새 PID의 Source·History 복구를 인수하고, 보존 종료 뒤 이전 root의 선택·백업·재생·reader 참조와 열린 writer·FD가 모두 해제됐는지 확인한다. S/Q root와 저장 namespace의 신원을 대조해 다른 설치가 공유하는 CAS·Catalog·mount가 없는 범위만 운영 퇴역 대상으로 승인한다. 실제 운영 경로 또는 독립성이 확인되지 않은 root는 `BLOCKED`로 둔다.
3. **공유 root의 전용 객체 회수.** 새 root의 선택 CAS 이후에도 이전 Catalog의 BOOT와 view 참조는 보호된다. `Reconfigure`는 제외 instance의 member를 제거해도 `projections`를 유지한다. owner가 빈 `ProjectionAdvance`도 certificate와 Source root를 보유한다. Q Catalog/GC와 S Store는 유지 데이터의 결속을 보존하면서 전용 참조를 해제하는 실제 경로를 검증한 뒤 회수한다. 필요한 해제 경로가 없으면 해당 범위는 `BLOCKED`다. 동일 root 운영 절체는 별도 제품 요구가 있을 때 설계한다. ## 완료 조건과 회수 증거

- **이전 저널 재오픈**은 실제 `RepoMapBundle` 완료 행과 정산 대상, 유지 ingest 행이 함께 있는 이전 root를 사용한다. 이전 실행물과 D가 실제 사용하는 판독 경로에서 미결 정산·receipt 검증·일반 Source 조회가 성공해야 한다. 검증 실패 시 이전 root의 in-place 수정·회수는 보류한다.
- **Source 발행 중 회수 방지**는 memo 캡처 전부터 closeout까지 같은 lease가 유지되는 프로토콜에 의존한다. Source pointer CAS와 RecordOnly ancestry의 기존 FNL410 회귀 두 건을 등록했다. Rust 실행은 **0/2 NOT_RUN**이다. 제품 재시작과 실제 CAS 회수는 각자의 원 수용에서 판정한다.
