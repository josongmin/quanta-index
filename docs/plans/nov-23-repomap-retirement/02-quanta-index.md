# 02 · Quanta Index 공개 계약과 서빙 퇴역

### 공개 contract 잔여

후보는 Q SDK namespace와 IPC 호출·태그, 구 query·Native/imported rank DTO의 제품 공개 및 전용 query engine/core port를 제거했다. 구 인코더 검증용 DTO는 테스트 fixture에 남는다. Q 내부 잔여 호출은 정적으로 정리했지만 S 호출 전환과 같은 후보 컴파일은 **미완료**다. 이전 저장 경로와 독립 Graph가 같은 모듈의 다른 타입을 쓰므로 그 물리 판독과 공용 타입은 유지한다. 구 query 요청·결과·focus와 Native rank DTO는 query 전용이며 `RepoMapSnapshotMeta`·Node/Edge 및 Graph persisted row는 물리 판독 또는 독립 Graph에 쓰인다. S 호출 제거 뒤 core의 query trait와 구 query engine을 물리 pin 검증에서 분리하고, 구 인코더 거절 fixture는 테스트 전용 wire 형식으로 남긴다.

### 구현 중 확인한 staging 경계

`stage_projection_output[_with_children]`과 `stage_immutable_object_v1`은 정책·producer 식별자가 없는 불투명 바이트 API다. 이 호출 자체가 퇴역 소유자의 바이트 예약을 구별한다고 가정하지 않는다. 후보 코드는 owner·certificate/profile staging, submit 및 재개에서 고정된 이전 producer 또는 rank 정책을 거절한다. Repo/revision별로 파생된 이전 projection·instance ID는 일반 요청만으로 식별할 수 없으므로, 다른 producer·정책을 섞은 재등록까지 거절하는 서명된 route/profile 정책과 실제 본문 확인은 **미완료 · NOT_RUN**이다. 후보 코드에는 BOOT V2와 selection schema 3의 정책 참조 및 Q 절체 시 보유한 이전 `repomap_heads`와 후보 정책을 대조하는 코드가 추가됐으며, Legacy imported head는 고정 ID를 공유하므로 물리 profile을 통한 실제 ID 인증과 중복 정규화 코드를 추가했다. 정책 export·서명된 활성화 증거·재시작 후 입장 적용은 미완료이며 Rust 검증은 **NOT_RUN**이다. 이전 `repomap_heads`와 해당 물리 profile에서 실제 instance·projection 결속을 인증하고 중복을 정규화한 뒤 이를 서명된 설치 설정 또는 별도 신규 서명 증거와 selection·BOOT에 결속해 재시작과 staging/submit/resume에 전달하는 계약이 필요하다. 현 selection 문서는 자체 서명이 아닌 canonical SHA와 flock/CAS로 보호되므로 selection의 digest만으로 서명 결속을 주장하지 않는다. policy body에 candidate config SHA가 들어가므로 그 digest를 다시 config에 넣으면 순환한다. 서명된 config의 생성 규칙을 고정하고 별도 서명 활성화 증거로 config SHA·selection SHA·V2 BOOT/policy ref를 결속하는 비순환 경로가 필요하다. 보호 Source route가 있는 후보의 정책 생성 순서는 이전 route 보유·policy export → 새 Q 객체 staging → S Source route journal·seal 입력 → V2 BOOT seal → handoff·SelectCandidate 재확인 → schema-3 selection·S FD6 target → 실제 절체 재검증이어야 한다. 이전 설치가 RepoMap-only라 새 Source head가 0건이면 새 workspace나 route를 만들지 않는다. 정책 객체만 별도로 stage하고 Source route 없는 V2 BOOT에 보호한 뒤 선택해야 한다. 이 경로의 Q 봉인과 S intent·handoff 연결은 추가됐으나 Rust 실행은 **NOT_RUN**이다. 기존 V1 BOOT을 FD6 작성 뒤 재봉인하면 target identity가 달라진다. 임의 메모리 denylist는 이 조건을 충족하지 않는다. 예약된 미참조 객체의 회수는 [저장 계획](03-storage-retirement.md)에 따른다.
