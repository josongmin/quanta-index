## Target contract

```text
Semantica HIR projection ───────────────────────── direct typed records ───────────┐
SDK plain/Markdown adapter ─┐                                                       ├─ SearchCorpusBatch → current text engine
External format adapter ────┴─ SourceAdapter<Input> → PreparedSource → SourceBatch ──┘        → receipt → CAS
Future native media adapter ─── typed contribution (after engine capability exists) → future typed materializer/query route
```

1. `SearchCorpusBatch` remains the **current text-lane engine primitive**. `ChunkRecord` alone is lexical-only; typed `SemanticSourceRecordV1` is required for semantic derivation. Semantica keeps HIR/card boundaries and its direct batch route. Do not assert that this wire body represents every future modality.
2. Add a small public `SourceAdapter<Input>` trait, opaque `PreparedSource`, `SourceContext`/`SourceKey`, `PriorSourceManifest`, and `SourceBatch` lifecycle. It is a compile-time adapter seam, not a daemon plugin registry or a universal raw-byte parser. `SourceBatch` lowers to one existing `SearchCorpusBatch` in V1; it must preserve the exact current publisher/receipt/CAS semantics without extra RPC.
3. Ship a **first-party plain/Markdown adapter** whose output is lexical chunks plus typed `DocumentLeaf` semantic sources under one `PreparedSource`. Prove the seam with a second test adapter accepting a different input type. Future code/config/PDF/image adapters may use the seam, but native media needs new typed engine capabilities; no text-field placeholder or silent fallback.
4. Public source DSL: `adapter.prepare(context, input)?`, `SourceBatch::{replace,delete,move_source}`, `client.sources().publish(&batch)?`, explicit activation. The direct `SearchCorpusBatch::{replace_scope,replace_semantic_scope}` path remains public. Text policy and parser specifics live in the text adapter, not the common lifecycle types.
5. **Lexical mutation ownership is one path per batch**, because Tantivy deletion, text authority retirement, structural auxiliary state, and readiness currently retire by path. `doc_surface` remains classification/clear metadata, not an independently replaceable scope at the same path. Admission rejects multiple lexical mutations for one path, including across surfaces and replace-vs-tombstone, before durable intent. This is a deliberate breaking tightening of current `(surface,path)` duplicate validation. No Tantivy schema migration is needed. A producer that needs chunk and symbol rows at one path puts them in one replacement scope; whole-surface clear behavior must remain independently tested. If that representation cannot preserve Semantica's current semantics, **stop V1** and implement true `(surface,path)` isolation across *all* indexes/ledgers with an explicit persisted-generation rebuild plan. Never patch only `delete_scope_docs`.

### Public behavior details to freeze in Gates 4–5

- `SourceKey` is canonical repo-relative path plus stable source owner ID. Validate `.`/`..`, absolute paths, separators and empty segments explicitly; `RepoRelativePath::new` alone is not sufficient validation. Keep repo/revision in `SourceContext`, and require them to match the batch. Media type and adapter recipe identify preparation, not engine support.
- `PreparedSource` fields stay private and expose typed constructors/builders for *currently supported* contributions. The text adapter owns one lexical path and one semantic owner and cannot drop either leg. A lexical-only custom adapter must declare that reduced coverage explicitly. Persist a `PriorSourceManifest` of old scope keys and recipe identity for delete/rename; do not persist an SDK-specific prepared IR.
- The text adapter uses existing `Chunk` lexical surface and `DocumentLeaf/File` semantic scope. Multi-source batch composition requires unique lexical paths and semantic owner IDs. Scope identity does not include content/revision; record IDs and digests do. Existing batch digest remains the authority for submitted bytes. No binary asset is inserted into a text field.
- Source input bytes, emitted lexical bytes/count, typed semantic bytes/count, and final batch capacity have checked limits. No transform claims exact source spans unless its offset mapping is exact. Publish failures do not silently switch modes.

## Integration order and ownership

- **Serial contract integrator:** Gate 0, contract admission, SDK canonical ordering, and final merge. This writer owns public API and wire digest behavior. Merge Gate 1 before adapter work is admitted.
- **Shared SDK writer:** Gate 4 source/result/batch contract after Gate 1, with SDK/public API files exclusively owned. This writer integrates exact lowering with `lexical.rs` and reuses the publisher.
- **Independent text-adapter writer:** Gate 5 parser/policy module and fixed fixtures after Gate 4 public seam is frozen; no edits to contract, SDK batch builder, Semantica, or daemon. Hand off typed output and goldens to integrator.
- **Independent resource writer:** Gate 3 core/config/resource E2E after Gate 1 admission shape; do not change SDK preparation. Integrator resolves constructor/config call-site changes and runs full tests.
- **Semantica writer:** Gate 2 after Gate 0 fixture proof and Gate 1 accepted contract; exclusively owns producer files. Gate 6 SDK integration and cross-repo receipts follow serially. Re-freeze both HEADs and dirty fingerprints at every handoff; a changed source invalidates earlier admission evidence.

## Verification rails and exit criteria

1. **Owner local:** focused contract/lexical/core/SDK tests via `./scripts/cargow` and applicable `just` targets; Semantica focused `q-test-*` and `just lint-spa05-fences`. Verify independent fixtures rather than reproducing implementation calculations in expected values. Run `just rust-public-api` after API/baseline changes and module boundary checks after module edits.
2. **Quanta integration:** `just rust-profile test-fast`, `just rust-profile test-integration-fast`, `just rust-profile test-integration-semantic`, `just rust-profile test-daemon-fast`; then `just rust-profile test-daemon` and the reference-client scenario on a clean checkout. Capture exact commands, exit codes, source SHA/dirty state, config/embedding backend, logs, artifact paths and digests, and excluded scope. Use actual activation/CAS and restart results, not compilation as evidence.
3. **Semantica compatibility:** source-bound full-loop test, same-path chunk+symbol fixture, delta/clear/replay scenario, ingress-only and SPA05 fences; select exact package/feature command from its Justfile at execution. Record Semantica SHA and Quanta SDK dependency identity together.
4. **Performance:** with deterministic local embedder and fixed fixture sizes, compare baseline vs candidate batch build time, publish latency, peak RSS, serialized bytes, and text-authority rebuild count for one near-limit document and a many-document batch. A benchmark run is evidence of cost only when source/config/workload and raw samples are retained; no speedup claim is required for this feature.
5. **Stop/reopen:** stop if Semantica cannot coalesce lexical scopes per path while preserving clear/delta meaning; if typed `DocumentLeaf` cannot express required text provenance; if the admitted maximum exceeds measured memory envelope; or if a clean-source Semantica direct-path test fails. Reopen the appropriate contract/producer decision instead of layering an exception in the SDK helper.

This first cut implements the **format-extension seam**, plain/Markdown, and a custom-adapter proof. It does not implement PDF/OCR/HTML or native image/audio/video indexing yet. Those are planned as adapters or explicit new engine capabilities under the parent RFC; this is not a permanent scope exclusion. Completion of this cut requires clean-source SDK + daemon + Semantica receipts. Arbitrary transformation chains, daemon runtime plugins, and silent model/ranking changes are outside the design.
