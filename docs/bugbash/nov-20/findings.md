## 확인된 문제와 잔여 작업

### ANN-01 · 기존 workspace의 쓰기 활성화

포맷 4의 이전 뷰는 Graph로 읽을 수 있다. Lance writer는 현재 선택 디렉터리가 포맷 4이면 쓰기 전에 `RebuildRequired`를 반환한다. 문제는 기존 루트를 쓰기 가능으로 활성화할 때 이 오류가 첫 갱신까지 늦어진다는 점이다. 일반 Serve의 recipe 검사와 candidate BOOT 검사는 이 경우를 가려내지 않는다. BOOT가 보존하는 루트에는 선택된 Semantic coverage가 포함되지 않는다. [제품 시작](../../../crates/quanta-index-searchd-runtime/src/native_product.rs#L1933) · [BOOT 보호 루트](../../../crates/quanta-index-catalog/src/native/authority/boot_manifest.rs#L63) · [쓰기 전 거절 회귀](../../../crates/quanta-index-semantic/src/native/embedding/tests/ann_product_tests.rs#L953)

**설치 경계.** launcher는 후보 FULL 게시·정상 종료·BOOT 검증 후 Legacy→Native 선택을 CAS로 게시한다. Native→Native 루트 교체와 Legacy rollback은 명시적으로 거절한다. BOOT와 selection 파일의 잠금만으로는 기존 Catalog에 어디까지 게시됐는지, producer에 미전송 작업이 남았는지 증명할 수 없기 때문이다. [후보 구축](../../../tools/deployment/launcher.py#L1178) · [전환](../../../tools/deployment/launcher.py#L1450) · [복귀](../../../tools/deployment/launcher.py#L1544)

**수정 순서.** 쓰기를 허용할 workspace·instance의 선택 뷰를 pin하고 기존 Semantic 경로의 view·profile·coverage·directory 검사를 공유한다. 유효한 coverage에 검색 디렉터리가 없으면 첫 Lance 쓰기를 허용한다. 포맷 5는 계속 쓰고, 포맷 4는 기존 읽기 pin을 보존하며 새 루트 재구축을 요구한다. coverage 자체의 누락·손상은 기존 오류로 처리한다. 운영 중인 Native 루트를 교체할 때는 producer 쓰기를 fence하고 미결 작업을 정산한 뒤 기존 Catalog 게시 기준선과 새 루트의 원본 입력·SourceCut을 대조한다. 쓰기 가능 판정을 그 상태와 selection CAS에 결속해 검사 후 새 게시가 끼어들면 전환을 거절한다. 구·신 뷰 읽기, 첫 쓰기, 재시작, stale CAS와 중단 시 선택 보존을 검사한다. 이미 새 쓰기를 받은 뒤의 복귀에는 그 쓰기까지 재생·대조한 증명이 필요하다. [뷰 pin](../../../crates/quanta-index-kernel/src/update.rs#L1856) · [선택 coverage 인증](../../../crates/quanta-index-semantic/src/native/embedding.rs#L2257) · [기존 전환 거절 회귀](../../../tools/ci/tests/test_deployment_launcher.py#L2275)

### ANN-02 · 선택 리전의 읽기·해시·재개방 비용

기존 hydration은 한 청크 파일도 multipart로 제출했다. pinned `InMemoryUpload::complete`는 모든 part를 새 연속 버퍼에 복사한다. 선택 경로를 **검증한 파일당 PUT 한 번**으로 바꿨다. 단일 청크의 `Bytes`는 원본 `StoredObject`와 할당을 공유한다. 여러 청크는 검증된 순서로 한 번 결합한다. 새 회귀는 단일 청크의 포인터 일치, 빈 파일, 여러 청크의 내용과 순서, freeze 후 쓰기 거절, 마지막 핸들 해제 후 메모리 반환을 검사한다. [선택 파일 저장소](../../../crates/quanta-index-semantic/src/native/ann_store/selected.rs) · [pinned PUT 변환](../../../vendor/object_store-0.13.2/src/payload.rs#L165) · [기존 multipart 복사](../../../vendor/object_store-0.13.2/src/memory.rs#L519) · [집중 회귀](../../../crates/quanta-index-semantic/src/native/ann_store.rs#L837)

진단 캡처를 켜면 기존 `query_candidate` 아래에서 네 구간을 구별한다. `query_ann_file_set`은 관리 객체 읽기·해시·seal 대조, `query_ann_hydrate`는 사설 store 재구성, `query_ann_open`은 연결·테이블·인덱스 검증, `query_ann_candidate`는 후보 요청·선택 검증·원본 재채점이다. 중단된 span은 종료 시각을 추정하지 않는다. 첫 구간에 모인 물리 I/O와 해시 CPU, 마지막 구간의 벡터 탐색과 재채점은 이 trace만으로 개별 귀속할 수 없다. [제품 계측](../../../crates/quanta-index-semantic/src/native/embedding/ann_query.rs#L550) · [trace 규격](../../../tools/benchmark/retrieval/causal_timeline.schema.json#L239)

**불변 descriptor의 파일셋 검증 수정.** 이전 판독기는 같은 캡처에서 같은 descriptor가 두 파일셋을 가리키는 관측을 수락했다. 판독 단계에서 null이 아닌 descriptor와 파일셋의 결속을 검증한다. 같은 조합의 반복, 서로 다른 descriptor의 파일셋 공유, 허용된 null은 보존한다. 단일 캡처 내부의 일관성 검사이므로 재시작 전후 파일의 결속은 설치·조회 관측으로 따로 대조한다. [제품 descriptor 검증](../../../crates/quanta-index-semantic/src/native/embedding/ann_directory.rs#L1092) · [판독기](../../../tools/benchmark/retrieval/causal_cost_timeline.py#L1151)

**부분 캡처와 빈 파일.** 부모 span이 유실돼도 관측 자체의 중복과 같은 파일셋의 상충하는 행·파일·청크 수는 검출한다. Lance manifest는 전체 데이터가 양수이면 빈 파일을 허용하므로 파일 2개와 청크 1개를 기록·판독할 수 있어야 한다. HNSW는 그래프 객체 1개를 파일 1·청크 1로 기록한다. [manifest 계약](../../../crates/quanta-index-semantic/src/native/ann_files.rs#L353) · [데몬 기록기](../../../crates/quanta-index-searchd/src/app/trace_recorder.rs#L839) · [빈 파일 회귀](../../../tools/ci/tests/test_causal_cost_timeline.py#L1296)

**열린 작업.** 전체 리전 descriptor의 centroid를 검사하는 `route_regions`는 첫 `query_candidate` span **앞**에 있다. 선택 descriptor 재디코딩, 전체 청크 인증, 테이블 열기도 조회마다 발생한다. 같은 뷰·질의의 cold/warm 비교에서 라우팅 시간·descriptor 수, 논리 청크 바이트, 실제 저장소 읽기·복사 바이트, open 시간과 peak RSS를 분리한다. 단일 청크는 hydration에서 backing을 공유하며 `read_retained`의 물리 I/O는 adapter에 달려 있다. 반복 인증·open이 지배하면 불변 파일셋에 결속한 검증 결과와 새 요청의 reader를 분리한다. 현재 store는 생성 요청의 deadline·취소·grant를 보유한다. 그대로 요청 간 공유하면 첫 요청의 만료가 다음 조회에 전파된다. 새 요청 비용 귀속, 별도 상한과 회수, old pin·교체·손상·취소에서의 동작을 검증해야 한다. [라우팅 경계](../../../crates/quanta-index-semantic/src/native/embedding/ann_query.rs#L1005) · [청크 검증](../../../crates/quanta-index-semantic/src/native/ann_files.rs#L814) · [store의 요청 소유권](../../../crates/quanta-index-semantic/src/native/ann_store.rs#L421)

### ANN-03 · 동일 아티팩트의 반복 디코딩

Lance의 기존 refill은 같은 후보 tuple만 기억했다. 같은 member의 다른 vector ID는 원본 아티팩트를 다시 디코딩했다. 현재 선택 리전 안에서 검증된 member reference로 다중 벡터 아티팩트를 재사용한다. 각 후보의 현재 coverage·input·vector ID 및 파일 적격성 검증은 계속 적용한다. 원본을 캐시하는 동안 decode 메모리 grant를 유지하고, 필수 할당에서 메모리가 모자라면 같은 WorkBudget이 선택적 캐시를 회수한다. [원본 재채점](../../../crates/quanta-index-semantic/src/native/embedding/ann_query.rs#L471) · [메모리 회수](../../../crates/quanta-index-core/src/index/budget.rs#L556) · [다중 벡터 및 메모리 한계 회귀](../../../crates/quanta-index-semantic/src/native/embedding/tests/ann_product_tests/lance_cache.rs#L6)

**회귀가 검사하는 조건.** 같은 member의 다른 벡터가 다시 등장할 때 정상 예산에서는 해당 아티팩트 읽기 1회를 요구한다. 한도 회귀는 A·B의 벡터를 교차시키고, 캐시를 끈 동일 조회에서 측정한 재채점 peak를 캐시 사용 조회의 상한으로 적용한다. 다음 필수 decode, 독립 cosine·파일 순위, 거절 기록과 종료 후 메모리 반환을 검사한다. 반복되는 coverage 조회와 리전 간 재사용 비용은 별도 측정 대상이다.

### ANN-04 · 파일별 후보 보충과 라우팅 손실

전역 heap이 차면 기존 코드는 재채점한 벡터마다 진척을 1로 셌다. 다음 리전의 여러 벡터가 같은 파일이어도 `top_k`를 채워 다른 파일을 보기 전에 멈출 수 있었다. 현재 파일 질의는 **인증된 서로 다른 소스 파일 수**, 벡터 질의는 **서로 다른 후보 벡터 수**로 진척을 센다. 파일의 전역 heap 진입 여부는 진척에 영향을 주지 않는다. prefix 재조회 비용은 같은 누적 예산을 쓰고 변경된 입력 stamp는 거절한다. [후보 보충](../../../crates/quanta-index-semantic/src/native/ann_lance.rs#L602) · [제품 분기](../../../crates/quanta-index-semantic/src/native/embedding/ann_query.rs#L693) · [동일 파일 tail 및 벡터 모드 회귀](../../../crates/quanta-index-semantic/src/native/ann_lance.rs#L1300)

9번째 리전만 전역 최상위 파일을 갖는 기존 Graph 회귀를 포맷 5의 실제 Lance 파일 검색까지 확장했다. 같은 고정 입력에서 전역 exact 1위는 owner 9, centroid가 선택한 8개 리전 안의 1위는 동점 규칙에 따라 owner 1이다. 응답은 탐색 제한을 표시해야 한다. 이 예제는 작은 flat 리전을 쓴다. 8개 리전인 원 ANN4K는 훈련 인덱스와 필터별 recall을 검사한다. [9리전 oracle](../../../crates/quanta-index-semantic/src/native/embedding/tests/ann_product_tests/maintenance.rs#L6143) · [원 ANN4K](../../../crates/quanta-index-semantic/src/native/embedding/tests/ann_product_tests/ann4k_tests.rs#L397)

**훈련 리전 라우팅 회귀.** 실제 Lance 리전 9개에 256행씩 설치하고 각 seal의 `IvfHnswSq`를 검사한다. 고정 질의의 전역 exact 1위는 centroid 상위 8개에서 제외된다. 독립 cosine으로 구한 전역 top-10과 선택 리전 top-10의 교집합은 9건이다. 회귀는 실제 ANN이 선택 리전의 top-10을 반환하며 `capped=true`인지 검사한다. 이는 의도적으로 만든 라우팅 손실 사례다. 선택된 coverage의 희소·상관 필터 Q64와 Recall@10 ≥0.95는 원 ANN4K가 계속 소유한다. [훈련 9리전 회귀](../../../crates/quanta-index-semantic/src/native/embedding/tests/ann_product_tests/ann4k_tests.rs#L581) · [필터별 적격 집합](../../../crates/quanta-index-semantic/src/native/embedding/tests/ann_product_tests/ann4k_tests.rs#L919)

**공유 소스 파일 회귀.** 점수가 낮은 증분 파일 두 개로 전역 top-2를 먼저 채운다. 이어 실제 Lance flat 리전의 가장 가까운 projection owner 64개는 한 파일, 65번째 owner는 두 번째 파일에 연결한다. 첫 후보 창을 보충해야 두 번째 파일이 기존 증분 결과를 교체할 수 있다. 회귀는 두 소스의 참조·경로와 원본 cosine 1·0, 스캔한 owner 67개를 검사한다. 원 4K의 여섯 비어 있지 않은 필터 구간도 선택된 coverage의 owner 집합을 기준으로 한다. ### ANN-05 · 조회 입장과 쓰기·병합 예산

기존 조회용 저장소는 쓰기와 mutation을 각각 4,096회 선차감했다. 새 생성자는 인증된 파일 `F`개에 대해 사설 PUT을 정확히 `F`번 수행한 뒤 store를 freeze한다. 총 operation 한도가 `M`이면 쓰기·mutation은 각 `F`, 이후 읽기는 최대 `M−F`로 원 예산에 귀속한다. 실패하거나 취소된 생성자는 쓰기 가능한 핸들을 반환하지 않는다. 3회분의 쓰기·mutation만 남긴 회귀로 예전 선차감이 거절하던 입력을 검사한다. [선택 저장소 입장](../../../crates/quanta-index-semantic/src/native/ann_store/selected.rs) · [비용 귀속](../../../crates/quanta-index-semantic/src/native/ann_store.rs#L391)

**열린 작업.** 조회의 전체 바이트 선예약과 writer의 `행 데이터 × 4 + 1 MiB` staging은 남아 있다. 정상 update와 burst 교체·삭제에서 실제 소비, 예약, 최초 거절 축, 재학습·설치 후 인증 시간, old pin 유지 중 재기록 바이트와 공간 부채를 기록한다. 합법적인 입력의 거절이 재현된 단계에서만 예약 방식을 변경한다. carry가 지배하면 같은 뷰·삭제 가시성·실패 원자성을 보존하는 Lance 증분 인덱스 갱신과 비교한다. worker 기한 내 성공, 실패 시 이전 publish와 pin 보존이 합격 조건이다. [writer](../../../crates/quanta-index-semantic/src/native/embedding/ann_materialization.rs#L430) · [carry](../../../crates/quanta-index-semantic/src/native/embedding/ann_directory/consolidation.rs#L632) · [Lance 증분 갱신](https://lance.org/guide/indexing/#maintain-indexes-after-appends)

**다중 범위 읽기의 바이트와 반환 객체 한도.** `abcd`에 요청한 `2..100`, `1..3`은 `cd`, `bc`를 반환해 4바이트를 소비한다. 읽기 실패 시 반환 바이트는 0이다. 기존의 호출당 작업 1회 차감으로는 작은 범위를 여러 묶음으로 읽고 보유할 때 반환 객체 수가 선예약량을 초과할 수 있었다. 이제 각 묶음은 backend 조회 전에 범위마다 작업 슬롯 하나를 함께 선점하고, 빈 묶음도 조회 한 번을 소비한다. 슬롯이 5개면 PUT 한 번과 범위 두 개짜리 묶음 두 번까지 들어간다. 현재 고정된 Lance reader에서 확인한 호출은 단일 범위 읽기다. [저장소](../../../crates/quanta-index-semantic/src/native/ann_store.rs#L589) · [EOF·겹친 범위 회귀](../../../crates/quanta-index-semantic/src/native/ann_store.rs#L1121) · [누적 범위 회귀](../../../crates/quanta-index-semantic/src/native/ann_store.rs#L1360)

**Multipart 제출 시점의 한도 검사.** 고정된 InMemory 구현은 part future를 반환하기 전에 payload를 보관한다. 래퍼가 future 안에서 용량을 검사하면 거절된 조각도 최종 파일에 합쳐질 수 있었다. 이제 제출 시 한도를 차감한 뒤 backend에 전달한다. 회귀는 7바이트 한도에 `abc`와 `defg`를 제출한 뒤 초과 조각을 먼저 poll하거나 future를 버려도 완료 파일이 정확히 `abcdefg`인지 검사한다. [저장소](../../../crates/quanta-index-semantic/src/native/ann_store.rs#L706) · [고정 backend](../../../vendor/object_store-0.13.2/src/memory.rs#L513) · [회귀](../../../crates/quanta-index-semantic/src/native/ann_store.rs#L1407)

**거절 원인의 수명.** 각 직렬 Lance 작업이 끝나면 해당 작업에서 기록한 첫 저장소 거절을 소비한다. vendor가 오류를 문자열로 변환한 경우에만 저장소의 원래 분류를 복원한다. 이미 분류된 취소·손상은 그대로 전파하고, 성공한 작업의 거절이 다음 작업의 오류를 바꾸지 않도록 했다. [세션 경계](../../../crates/quanta-index-semantic/src/native/ann_session.rs#L142) · [오류 회귀](../../../crates/quanta-index-semantic/src/native/ann_session.rs#L210)

파일셋 크기를 `S` 바이트(`S > 0`)라 하면 store 선차감은 리전당 `S + min(8S + 1 MiB, 64 MiB)`다. 이에 앞서 청크 인증이 같은 작업 예산에 `S`를 차감한다. 각각 8 MiB인 리전 8개를 모두 방문하려면 store 선차감 576 MiB와 인증 64 MiB로 이 두 경로에서만 **640 MiB**가 필요하다. 512 MiB 한도에서 중간에 거절된다. 이 수치는 논리 work bytes다. 실제 ANN4K의 512행 × 64차원 리전은 f32 벡터 원소만 128 KiB이며 완성 파일셋 크기는 실행에서 측정해야 한다. 실제 reads·파일셋 크기·최초 거절 축을 얻기 전에는 이 경계를 4K 지연 원인으로 채택할 수 없다. [청크 인증 차감](../../../crates/quanta-index-semantic/src/native/ann_files.rs#L764) · [리전별 한도 산식](../../../crates/quanta-index-semantic/src/native/embedding/ann_query.rs#L597) · [작업 선차감](../../../crates/quanta-index-semantic/src/native/ann_store.rs#L391)

### SourceAdvance 개선 순서와 포맷 변경 조건

1. **기존 Tree 제품 경로에서 비용을 나눈다.** 기존 4,096건 prefix 진단의 동일 operation에서 소스 적용, 텍스트 작성, 경로 맵 설치, coverage의 누적 논리 읽기 차액을 본다. 경로 설치 span 49는 `finish`만 감싸므로 파일별 scratch 수집은 별도로 계산한다. 기존 계측으로 분리되지 않는 경우에만 writer 단위로 제출한 배치·행 수, scratch 단계의 읽기 차액과 맵 설치의 객체·자식 검증 수를 기록한다. 중첩 span 합계로 비용을 중복 집계하지 않는다. 현재 패킹으로 같은 제품 테스트가 통과하면 이 실패에 대한 포맷 변경은 종료한다. 다른 단계가 예산을 지배하면 접근 대상도 그 단계의 생산자로 옮긴다. [경로 설치 span](../../../crates/quanta-index-lexical/src/native/text.rs#L14129) · [기존 prefix](../../../crates/quanta-index-searchd-runtime/tests/native_product_process/ann_quality/materialization_diagnostic.rs#L288)
2. **scratch 제출 비용이 크면 포맷을 유지하고 writer의 배치 수명을 고친다.** 파일별 지역 버퍼를 `PathWrites`가 소유하게 하고 기존 64행 한도와 마지막 잔여분에서 비운다. 이 고정 입력에서 24,576행의 INSERT 제출 수는 4,096회에서 384회가 목표다. 이후 정렬 스트림의 행별 읽기 과금은 그대로다. byte·memory 예약, 중복 키 거절, 실패 시 미게시를 유지한다. 동일한 정렬 편집 스트림과 root를 얻고, 실행에서 배치 수와 scratch 비용이 실제 감소하는지 확인한다. [파일별 flush](../../../crates/quanta-index-lexical/src/native/text_path.rs#L476) · [64행 계약](../../../crates/quanta-index-scratch-sqlite/src/lib.rs#L33)
3. **반복되는 객체 설치·자식 검증이 지배하면 경로 posting의 물리 단위를 바꾼다.** 목표는 불변 세그먼트 안의 경로 term 사전과 정렬된 로컬 문서 번호 블록이다. 세그먼트의 문서 번호를 안정된 owner에 대응시키고 소스 revision은 고정한 view의 SourceCut에 결속한다. 병합 시 로컬 번호를 다시 매기고 해당 블록과 함께 게시한다. 경로가 같은 본문 교체는 경로 posting을 재작성하지 않고, rename·삭제는 영향 범위의 membership을 변경한다. 본문에서 제외된 파일도 경로 문서 집합에 포함한다. 현재 Layered V2도 경로에는 같은 `PathWrites`를 쓰므로 레이아웃 선택만 바꾸어서는 이 구조가 생기지 않는다. 기존 본문용 정렬 docID 페이지·범위 병합과 Catalog의 원자적 게시·pin 수명을 재사용한다. 경로 reader와 writer는 새 물리 정책을 명시한다. 새 view를 게시하기 전 기존 root 재개방, 실패 시 이전 view 유지, merge 후 결과 및 참조 수명을 검증한다. 4. **독립 정답과 제품 한도로 채택한다.** 경로 결과를 원본 경로 전수 스캔과 대조한다. 대소문자·Unicode, 본문 미색인 파일, 본문만 교체, rename·삭제, 이전·현재 view와 재시작을 포함한다. 물리 포맷 변경 시 같은 입력·캐시 조건의 cold build, 단일 변경, 흔한 term·희소 term 조회에서 논리 읽기와 wall time을 비교해 조회로 전가된 비용을 확인한다. 이후 기존 admission과 직렬 실행기로 동일 Tree 제품 selector의 100만 읽기·1,200초 아래 초기 게시부터 오버레이 종료·두 번째 재시작까지 통과하고, 공통 소스·의존성이 맞는 ANN4K의 필터별 Q64 Recall@10 ≥0.95와 빈 결과를 확인한다. 새 포맷을 제품에 승격할 경우 해당 포맷으로도 같은 시나리오를 통과해야 한다. 기존 Text 전용 제품 회귀 6/6 및 독립 Tantivy 입력 검사는 각자 검증한 범위에서 재사용한다. ### 앞선 watchdog 실행의 후속 판정

앞선 두 watchdog 실행의 시작 시점 `ann_query.rs` SHA-256 접두사 `cd0ad91ea4ab`는 각 기록된 Git revision에서 Graph를 조회하는 코드와 일치하고, 이 파일은 양쪽 변경 목록에도 없다. 직접 확인한 공통 실패는 **여러 단계가 공유하는 1,200초 기한 소진**이다. 두 번째 실행의 마지막 IPC 기한 1,065ms도 남은 시간으로 잘린 요청과 일치한다. 초기 완료 관측 시간에는 worker 실행·관측 대기·마지막 coverage 확인이 겹친다. 두 수치의 차이를 provider, Catalog 또는 Lance의 CPU·I/O 시간으로 환산할 수 없다. [요청별 기한](../../../crates/quanta-index-searchd-runtime/tests/native_product_process/ann_quality.rs#L1363) · [완료 관측 경계](../../../crates/quanta-index-searchd-runtime/tests/native_product_process/ann_quality.rs#L705)

1. **원 실행에서 실패 구간을 고른다.** 기존 제품→ANN4K 직렬 실행기와 admission을 유지한다. 이번 확인에서 제품 실행기는 실제 preflight 파일을 갱신했고 ANN4K 실행기는 같은 직렬 잠금에서 기다렸다. 제품 단독 통과 후에는 새 ANN4K 결과와 공통 소스·의존성을 대조한다. 제품 실행기는 시작할 때 trace 환경변수를 비운다. Off 로그의 `quality-phase`, `work-status`(RPC·pause·최종 receipt 이후 시간), `quality-sweep`(SDK·로컬 oracle), provider 입력 수를 본다. harness와 daemon의 독립 시계 또는 worker 실행과 겹치는 polling 대기를 합산하지 않는다. [readiness 필드](../../../crates/quanta-index-searchd-runtime/tests/native_product_process/ann_quality/work_status.rs#L118) · [질의 시간 필드](../../../crates/quanta-index-searchd-runtime/tests/native_product_process/ann_quality.rs#L1294) · [선택적 trace 경로](../../../crates/quanta-index-searchd-runtime/tests/native_product_process/ann_quality.rs#L1688)
2. **지배하는 단계만 진단한다.** 초기 materialization이면 기존 4,096 source·128 완료 prefix의 Record 진단을 같은 admission 아래 직렬로 실행한다. 확인 시점에 기존 prefix의 trace 폴더는 비어 있었고 기록된 PID는 종료돼 있었다. 생성된 capture에서 receipt와 닫힌 worker의 prepare·coverage save·publish·compaction을 대조한다. `semantic_build`가 끝난 뒤 freeze·파일셋 설치가 실행되고 그 뒤의 `semantic_seal`이 설치물을 다시 인증한다. 두 span 사이 잔여 시간이 크면 snapshot·설치를 직접 계측한다. prefix에서 seal/carry가 발생하지 않거나 늦은 구간에서만 지연이 나타나면 그 작업을 담은 진단이 필요하다. [prefix 범위](../../../crates/quanta-index-searchd-runtime/tests/native_product_process/ann_quality/materialization_diagnostic.rs#L288) · [닫힌 worker 해석](../../plans/nov-12-native-cutover/tickets/NC-B-semantic.md#L711) · [build 이후 설치](../../../crates/quanta-index-semantic/src/native/embedding/ann_materialization.rs#L469) · [설치 후 seal](../../../crates/quanta-index-semantic/src/native/embedding/ann_directory.rs#L823)
3. **검색이 지배하면 같은 뷰·seed를 따라간다.** SDK 왕복, 로컬 exact 판정, overlay provider 호출을 먼저 대조한다. 현재 overlay는 적격 문서의 같은 revision도 질의마다 provider를 호출한다. 이 시간이 지배할 때만 workspace·session·owner·revision·입력 digest와 recipe에 결속한 벡터 재사용을 검토한다. 새 revision·삭제·종료가 즉시 반영되는지 검사한다. daemon 안의 시간이 필요하면 해당 검색을 실제 포함하는 Record로 좁힌다. 파일셋 검증·hydrate·open span을 비교하고, 기존 span 밖의 라우팅 또는 후보 span 안의 backend 실행·원본 재채점이 구분돼야 하는 지점만 추가 계측한다. prefix 진단은 overlay를 실행하지 않는다. 캐시·라우팅·설치 중 측정으로 설명되는 경로만 고치고, 최초 실패한 같은 Off selector로 제품 동작과 기한을 재검증한다.
