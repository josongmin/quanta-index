# Deep weak-assertion audit (core, lexical, ipc, embed, searchd-runtime, searchctl, catalog, contract)

Scope: tests asserting only `is_ok` / `is_err` / `is_some` / `is_none` / `unwrap` / `len>0` / `is_empty` / snapshot-exists without checking the tested behavior's value, code, identity, or count. Every cited file body was opened and read. `expect("...")` on fixture constructors (`RepoId::new`, tempdir) is setup, not a finding, and is excluded.

## Per-crate gap counts

## Findings

### core
- F1 `crates/quanta-index-core/tests/ingest_resource_policy.rs:247-250` — symptom: `zero_ceilings_are_refused_at_construction` asserts only `is_err` x3 + `is_ok` x1, never which field was rejected or the error code. Why bad: a constructor that rejects the wrong field (or all inputs) still passes. Severity: M. Fix: `assert!(matches!(IngestResourcePolicy::new(0,1,1), Err(CoreError::Typed{code,..}) if code == <expected>))` per arm, or at minimum distinct `expect_err` + code assert; mirror the strong `semantic_policy.rs:20-23` typed-code pattern.
- F2 `crates/quanta-index-core/tests/semantic_policy.rs:38` — symptom: `semantic_top_k_public_maximum_is_accepted` asserts `validate_top_k(max).is_ok()` without asserting the returned value / that `max == PUBLIC_TOP_K_MAX` is the same fact (second assert covers the const but not the validation result). Why bad: a validator returning `Ok(wrong_value)` passes. Severity: L. Fix: bind the ok value and assert it, e.g. `assert_eq!(SemanticPolicy::validate_top_k(max).expect("max accepted"), max)` or assert normalized output.
- F3 `crates/quanta-index-core/tests/semantic_policy.rs:278` — symptom: `assert!(refused.embed_batch(&["triple","nan"]).is_err())` checks refusal but not which vector failed, what code, or that tallies recorded nothing (the next line does assert tallies — good — but the error itself is unchecked). Why bad: any error including wrong-layer passes. Severity: M. Fix: `let err = refused.embed_batch(...).expect_err(...); assert_eq!(typed_code(&err), Some(<code>)); assert!(format!("{err:?}").contains("nan"))`.
- F4 `crates/quanta-index-core/tests/hybrid_policy.rs:185,237` — symptom: `rrf_top_k_zero_returns_empty` / `rrf_empty_inputs_returns_empty` assert only `fused.is_empty()`. Why bad (mild): empty is the whole contract here, but a function returning `vec![garbage]` trimmed elsewhere could still be masked; no score/order check possible on empty. Severity: L. Fix: also assert `fused.len() == 0` is redundant — instead assert the non-empty twin's exact ids/scores (already done at `:192-193`), or assert `fuse_rrf(&lex,&[],0) == Vec::new()` typed equality. No change strictly required; keep as-is with exact-eq form.

### lexical
- F5 `crates/quanta-index-lexical/tests/execution_budget.rs:339-340` — symptom: `zero_budget_is_refused_at_construction` asserts `new(0).is_err()` / `new(1).is_ok()` with no error kind. Why bad: same as F1 — wrong-field rejection passes. Severity: M. Fix: match typed code, e.g. `assert!(matches!(LexicalExecutionBudgetV1::new(0), Err(CoreError::Typed{code,..}) if code == ...))` and `assert_eq!(LexicalExecutionBudgetV1::new(1).unwrap().get(), 1)`.
- F6 `crates/quanta-index-lexical/tests/tantivy_smoke.rs:3536-3537` — symptom: `assert!(chunk_hits.is_empty()); assert_eq!(symbol_hits.len(), 1);` — len-only on the symbol side before the strong `candidate_id == "kept-symbol"` check at `:3541`. Why bad (mild): len==1 alone would pass with the wrong symbol; here the follow-up id assert saves it, so the finding is only that the len assert is redundant, not missing. Severity: L. Fix: drop the len assert or keep as guard; the id assert at `:3541` is the real predicate (positive model).
- Non-finding (checked): the ~25 `if !miss_hits.is_empty() { return Err(...) }` negative controls in `tantivy_smoke.rs` (e.g. `:870,920,985,1077`) look like `len>0` avoidance but each pairs with a positive `ids == [...]` oracle; not weak.

### ipc — no findings
- Audited `crates/quanta-index-ipc/tests/socket_access.rs`, `admission.rs`, `repo_admission_and_slowloris.rs`, `wire_historical_cbor.rs`, `g0r_runtime_cancellation_probe.rs`. All assertions read back counters, typed codes (`ERR_SERVER_OVERLOADED`, `REQUEST_DEADLINE_EXCEEDED`), file modes via `stat`, and dispatcher-reached counts. `expect()` uses are fixture setup only (`RepoId::new(...).expect("test fixture...")` at `admission.rs:205-207`, `socket_access.rs:204-206`). No snapshot tests.

### embed
- F7 `crates/quanta-index-embed/src/cache.rs:2497-2506` — symptom: `zero_ceilings_are_refused_at_construction` asserts five `is_err` + one `is_ok` with no per-field code. Why bad: wrong-field rejection passes; the `max_total >= max_resident` cross-check at `:2507-2510` is strong but doesn't cover the five arms. Severity: M. Fix: assert each arm's typed code / message mentions the field (`max_entries`, `max_resident_bytes`, `ttl`, ...), and bind the ok policy asserting `policy.max_entries() == 1`.
- F8 `crates/quanta-index-embed/src/cache.rs:1902` and `crates/quanta-index-embed/src/openai.rs:1350` — symptom: `assert!(provider.embed_batch(&["a"]).is_err())` with no error kind (incl. `max_retries_zero_disables_retry` at `openai.rs:1350`, where the strong part is the `calls == 1` knob proof at `:1351-1355`). Why bad: any error passes, including transport-misuse. Severity: L (the call-count assert carries the test). Fix: `let err = provider.embed_batch(&["a"]).expect_err(...); assert!(format!("{err:?}").contains("503") || matches!(err, CoreError::...))`.
- F9 `crates/quanta-index-embed/src/openai.rs:1472-1487` — symptom: constructor table (`with_max_batch(0)`, `with_concurrency(0)`, `cfg(0)`, `cfg(MAX+1)` → `is_err`; `cfg(MAX)` → `is_ok`) with no codes. Why bad: same ctor-table gap as F1/F5/F7. Severity: M. Fix: per-arm typed-code match + `assert_eq!(provider.dimension(), MAX)` on the ok arm (pattern exists at `openai.rs:963-964`).

### searchd-runtime
- F10 `crates/quanta-index-searchd-runtime/tests/runtime_supervisor_owner_v1.rs:215,267,325,363,407,586` — symptom: six `assert!(spawned.is_ok())` / `assert!(spawned_a.is_ok() && spawned_b.is_ok())` spawn preambles assert only success, never the child handle identity, readiness, or exit-code that the rest of the test then exercises. Why bad: a spawn returning the wrong child still passes the preamble; failure surfaces later far from cause. Severity: L (downstream `exit_code` asserts at `:169` etc. are strong). Fix: bind handles and assert names/ids, e.g. `let a = spawned_a.expect("child-a spawns"); assert_eq!(a.name(), "child-a")`, or `assert!(spawned.is_ok(), ...)` → `spawned.expect(...)` so the panic message carries context.
- F11 `crates/quanta-index-searchd-runtime/tests/runtime_supervisor_owner_v1.rs:160,162` — symptom: `assert!(first.is_ok())` / `assert!(second.is_err())` without checking the refusal code for the second spawn. Why bad: any error (including wrong-layer) passes the refusal arm. Severity: M. Fix: `assert!(matches!(second, Err(ref e) if <code or message contains "already spawned">))`; the rollback asserts at `:169-184` are already strong.
- F12 `crates/quanta-index-searchd-runtime/tests/state_migration_owner_v1.rs:793` — symptom: `assert!(typed_code(&error).is_some(), "got {error:?}")` — asserts *some* code exists, not *which* code. Why bad: wrong typed code passes. Severity: M. Fix: `assert_eq!(typed_code(&error), Some(SearchPlaneErrorCodeV2::<Expected>))` — the exact pattern used two tests away at `:487-490` and `:829`.
- F13 `crates/quanta-index-searchd-runtime/tests/state_migration_owner_v1.rs:473` — symptom: `assert!(!manifest.objects.is_empty())` — non-emptiness only, no count, digest, or expected object names after a post-rename failure. Why bad: a manifest with wrong/extra objects passes. Severity: M. Fix: `assert_eq!(manifest.objects.len(), N)` + assert the expected object id/digest set equals the pre-fault manifest.

### searchctl
- F14 `crates/quanta-index-searchctl/tests/cli_smoke.rs:76-136,742,778,879,896,930,988,1119,1152,1178,1204,1226` — symptom: ~24 one-line `#[test]` bodies of the form `assert!(result.is_ok(), "{result:?}")` delegating to `*_impl()`. Why bad (mild): the outer assert checks only success; all real predicates (`stdout.contains("\"kind\": \"Text\"")` at `:166`, `candidate_id` at `:169-171`) live inside the impl. A green outer assert can coexist with a gutted impl that returns `Ok(())` unconditionally — the strength is one refactor away from being lost. Severity: L (impl bodies currently strong — verified `lexical_json_roundtrip_impl` at `:139-173`). Fix: inline one content predicate in each outer test (e.g. have impl return the stdout string and `assert!(stdout.contains(...))` in the `#[test]` body), or add a meta-test asserting each impl body contains a `contains`/`==` check.
- No snapshot tests; no `len>0`-only asserts in this crate.

### catalog — no findings

No snapshot tests.

### contract
- F15 `crates/quanta-index-contract/tests/repomap_layout_v3_contract.rs:184,324` — symptom: mutation-rejection loops assert bare `decode_canonical(&mutation).is_err()` for 6+ byte mutations without asserting *which* canonical error (schema vs type vs digest). Why bad: a decoder that rejects everything with one generic error passes; canonical-code regressions invisible. Severity: M. Fix: `assert_eq!(decode_canonical(&m), Err(CanonicalRepoMapCodecErrorV1::<Specific>))` per mutation, as done for the positive case at `:172-175` (`EvidenceBindingMismatch`).
- F16 `crates/quanta-index-contract/tests/repomap_layout_v3_contract.rs:430-444` — symptom: evidence-combination table asserts bare `is_err`/`is_ok` per reason class without naming the refusal reason. Why bad: cross-wired reason classes (e.g. `AddressDigestMismatch` vs `NonCanonicalSourceAddress` arms) pass as long as err/ok polarity matches. Severity: M. Fix: match the error payload per arm (`assert!(matches!(evidence(...), Err(CanonicalRepoMapCodecErrorV1::...)))`).
- Checked non-findings: `lxe_unified_surface.rs:339-344`, `ipc_control_quarantine_contract.rs:268,321`, `scv2_01_semantic_source_wire.rs:126-145` `is_empty` uses are field-emptiness branches inside otherwise exact decode-compare tests, not standalone assertions.

### contract-base
- F17 `crates/quanta-index-contract-base/tests/canonical_identity_v1.rs:25-26,33-38` — symptom: serde refusal arms assert bare `from_str::<RepoId>(&wire).is_err()` while the constructor arms assert exact `Err(IdentityValidationErrorV1::Empty/ControlCharacter/NonCanonical/TooLong)`. Why bad: constructor/serde parity (the test's stated goal) is half-proven; a serde layer rejecting with the wrong error passes. Severity: M. Fix: `assert_eq!(serde_json::from_str::<RepoId>(&wire).unwrap_err().to_string(), ...)` or map to the same `IdentityValidationErrorV1` variant per arm.
- F18 `crates/quanta-index-contract-base/tests/query_truth_owner_v1.rs:127,129,140` — symptom: cursor tamper matrix (wrong key, expired, tampered body) asserts bare `is_err()` without asserting the failure is a signature/expiry refusal vs a decode error. Why bad: a decoder that fails closed for the wrong reason (e.g. base64 error instead of signature mismatch) passes. Severity: L (the `matches(&binding("repo-b"),1)` negative at `:142` and round-trip at `:122-123` are strong). Fix: assert error variant/message per arm (`...expect_err` + `contains("signature")` / `contains("expired")`).

## Strong tests (positive models)

1. `crates/quanta-index-core/tests/hybrid_policy.rs:241-251` (`rrf_key_fusion_matches_independent_oracle_across_rank_shapes`) — asserts `actual == slow_rrf_oracle(&lanes)` exact equality against an independent oracle, plus permutation-invariance (`:253-267`) and prefix property (`:269-287`). Model: oracle + invariant + boundary sweep, not just `len>0`.
2. `crates/quanta-index-lexical/tests/planner_authority.rs:169-205,208-218` (`assert_typed_error` / `assert_not_implemented` helpers) — every planner refusal asserts the exact `SearchPlaneErrorCodeV2` code and message fragment, failing with `expected typed code X, got ...`. Model: reusable typed-error helper reused across all refusal tests.
3. `crates/quanta-index-ipc/tests/admission.rs` (whole target; e.g. overload/deadline proofs) — asserts typed refusal codes (`ERR_SERVER_OVERLOADED`, `REQUEST_DEADLINE_EXCEEDED` with checkpoint name), barrier/channel ordering, *and* reads the outcome back from server counters the way a scrape does. Model: error code + ordering handshake + independent counter oracle.
4. `crates/quanta-index-catalog/tests/auxiliary.rs:213-251` (`a_batch_that_cannot_be_written_writes_nothing`) — asserts `expect_err` + `matches!(InvalidContract(_))` + ledger-empty + catalog-still-usable (`len() != 1` follow-up). Model: error kind + atomicity (nothing-half-written) + recovery.
5. `crates/quanta-index-embed/src/cache.rs:2521-2557` (`the_ledger_expires_entries_past_the_age_cap_on_lookup_and_on_write`) — asserts exact `Touch::Hit/Expired/Miss` transitions and exact stats tuples `(expirations, misses, hits, entries) == (1,2,2,1)` then `(2,1,8)`, plus exact expired id list. Model: state-machine transitions with exact counters, not `is_some`.

## Proposed fix priority

1. M-severity error-kind gaps first: F1, F5, F7, F9 (ctor tables), F15/F16 (canonical codes), F17 (serde parity), F11/F12 (supervisor/migration codes), F3/F13.
2. Then L-severity hardening: F8, F18, F2, F6, F10, F14 (outer/inner split), F4 (cosmetic exact-eq).
3. No snapshot-exists-only tests were found in any of the eight crates; no action there.
