## Closure

- 각 티켓 `Reuse`의 `DONE_IMPL`은 명시된 구현 연결만 뜻한다. `HELPER_IMPL`은 helper/API 본문만 있고 생산 caller가 미연결인 경우, `STRUCTURE_VERIFIED`는 명시된 구조 검사만 통과한 경우다. ANN은 `PRIVATE_CODE_PRESENT`다. 모두 전체 티켓/제품 검증 완료와 구분하고 같은 helper/알고리즘을 다시 만들지 않는다.
- 작업 착수, 코드 연결 변경, blocker/첫 결과 발생, 검증 종료 시 해당 행을 갱신한다. 변동 없는 재감사로 새 현황 문서를 만들지 않는다. 실제 코드가 바뀌면 해당 행과 개별 범위만 수정한다. 명령·source·scope별 결과는 VALIDATION에 한 번 기록하고 여기에는 필요한 잔여만 반영한다. 새 dated 현황/최종 감사 절을 누적하지 않는다.
- `CHECKS`인 W2-01/03/04/07/08/11/15/17/19는 새 기능 구현 착수 큐가 아니다. `HANDOFF+CHECKS`인 W2-14는 기존 W2-05/06 producer 결과를 인수하며 수신 엔진을 재작성하지 않는다. 코드 결함이 확인되면 기존 티켓에 exact path/caller·실패 근거와 좁은 수리만 반영한다. `HELPER_IMPL`인 W2-05는 기존 public helper/authority에 실제 caller를 연결하고, `PRIVATE_CODE_PRESENT`인 W2-13은 기존 ANN 초안을 소비한다. W2-10은 측정 전 개발하지 않는다.
- W2-05/06의 실제 producer 연결은 SDK가 소유하고 INT는 Required/AA 통합만 소유한다. 같은 producer의 semantic/graph 결과는 W2-12/14가 소비하며 별도 producer를 만들지 않는다. W2-09는 그 경로의 adapter/계측, W2-18은 검증된 target/selection 인계, W2-19는 수용이다. 각 단계가 같은 FULL/delta 엔진을 다시 구현하지 않는다.
- missing result·UNKNOWN·NOT_RUN은 구현 부재나 성공이 아니다. scoped green을 합산해 current full-suite/제품/성능을 VERIFIED로 만들지 않는다.
- legacy A/D/C5의 원 수용은 다시 구현하지 않는다. legacy LQ5/trace/운영 및 기존 test-platform·semantic·installed/pair/provider/release 미수용은 W2-07/09/10/19가 해당 기존 oracle를 유지한다. Native 진행만으로 지우지 않는다.
